3. **useGestureController.ts** — Единый gesture controller, заменяющий useFollowFingerSwipe + useTouchNavigation + IOSTapZones:

   **Интерфейс:**
   ```typescript
   export interface GestureControllerOptions {
     rendition: Rendition | null;
     enabled: boolean;
     onNavigate: (dir: 'next' | 'prev') => Promise<void>;
     onChapterChange?: (dir: 'next' | 'prev') => Promise<void>;
     onEdgeTap: (dir: 'next' | 'prev') => void;
     onCenterTap: (x: number, y: number) => void;
     onToggleUI: () => void;
     onSwipeStart: () => void;
     onTapNavigate: () => void;
     navLock: NavigationLock;
     isPanelOpen: boolean;
   }
   ```

   **Архитектура — координатор + FSM:**
   - FSM состояния: `idle` -> `pending` -> `swiping` | `tap` | `cancelled`
   - Все touch state — ref-based (без ререндеров на touchmove)
   - Реюзать ALL экспортированные утилиты из useFollowFingerSwipe: `getStageInfo`, `shouldNavigate`, `calculateVelocity`, `getRubberBandOffset`, `FOLLOW_FINGER_CONFIG`, все SPRING_* конфиги — импортировать напрямую, НЕ копировать
   - Реюзать `translateX` MotionValue, `triggerSlideAnimation`, boundary detection и rubber-band логику из useFollowFingerSwipe — перенести эту логику внутрь контроллера
   - Return type аналогичен UseFollowFingerSwipeReturn + дополнительные поля контроллера

   **Гибридный подход iOS/Android (решение архитектуры — Claude's Discretion):**
   - Свайп: всегда через `rendition.hooks.content.register()` (работает и на iOS, и на Android) — из useFollowFingerSwipe
   - Тапы в iframe: через hooks.content.register() на Android/desktop (из useTouchNavigation)
   - Тапы на iOS: сохранить overlay-подход (IOSTapZones паттерн) — iOS Safari не пробрасывает touch из iframe надежно
   - Контроллер управляет ОБОИМИ каналами событий

   **FSM логика:**
   - `idle` -> touchstart -> `pending` (записать startX/Y/time)
   - `pending` -> touchmove >10px horizontal -> `swiping` (делегировать follow-finger логику, вызвать `onSwipeStart()`)
   - `pending` -> touchmove >10px vertical с ratio >2.0 -> `cancelled` (вертикальный скролл)
   - `pending` -> touchend <350ms, <20px movement -> определить зону тапа:
     - Край (левые/правые 15% на iOS overlay, 25% через iframe) -> `onEdgeTap(dir)`, вызвать `onTapNavigate()`, `triggerSlideAnimation(dir)`
     - Центр -> проверить elementFromPoint на description, если нет — `onToggleUI()`
   - `pending` -> >350ms без end -> `idle` (long-press — не перехватывать)
   - `swiping` -> touchend -> анимация завершения (как в useFollowFingerSwipe) -> `idle`
   - При `isPanelOpen === true` — игнорировать ВСЕ навигационные жесты (свайп и тап по краю). Center-tap для toggle UI допускается

   **Блокировка тапов при свайпе:**
   - Навигация по тапу (onEdgeTap) использует navLock.acquire() + guaranteed-last паттерн из IOSTapZones (pendingNavRef)
   - Тап запускает triggerSlideAnimation параллельно с навигацией (non-blocking visual effect, как в Phase 10)

   **iOS overlay:**
   - На iOS: контроллер создает и управляет прозрачными overlay-элементами поверх iframe для center-tap detection (аналог IOSTapZones center zone)
   - Edge tap зоны на iOS НЕ нужны, т.к. follow-finger свайп работает через iframe и edge-тапы можно отлавливать через iframe hooks.content.register тоже (переход от 8% overlay зон к iframe-based определению зоны)
   - Если iframe touch events не работают на iOS для тапов — сохранить overlay для всех зон (гибридный подход уже проверен в IOSTapZones)
   - Center tap overlay: position absolute, covers center 70% ширины, top от safe-area, bottom до safe-area. z-index 5

   **ВАЖНО:** useFollowFingerSwipe.ts НЕ удалять — оставить как библиотеку утилит и spring-конфигов. Удалить только хук `useFollowFingerSwipe`, экспорты утилит оставить. useTouchNavigation.ts — удалить полностью (вся логика поглощена контроллером). IOSTapZones.tsx — если overlay нужен на iOS, упростить до чистого overlay без собственной gesture логики (контроллер управляет через ref callbacks).
