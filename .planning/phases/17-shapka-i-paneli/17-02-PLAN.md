<task type="auto">
  <name>Task 2: SearchPanel адаптация на 320px</name>
  <files>frontend/src/components/Reader/SearchPanel.tsx</files>
  <action>
Адаптировать SearchPanel для 320px viewport (HDR-02 -- поле поиска и кнопка закрытия полностью видны).

**Проблема:** На 320px input + statusText (min-w-[80px]) + nav buttons (2x w-9) + close button (w-9) = слишком много элементов в одной строке. statusText занимает фиксированное пространство и сжимает input.

**Решение:**

1. Скрыть statusText на экранах < 375px: добавить `className="hidden xs:inline ..."` к span с statusText. На 320px статус не показывается -- input получает больше пространства.

2. Уменьшить gap на маленьких экранах: `gap-1.5 xs:gap-2` вместо `gap-2` в основном flex контейнере.

3. Уменьшить горизонтальные padding: `px-2 xs:px-3` вместо `px-3`.

4. Фикс автофокуса SearchPanel на мобильных: добавить `useIsMobile` import и обернуть focus в проверку:
   ```tsx
   const isMobile = useIsMobile();

   useEffect(() => {
     if (isOpen && !isMobile) {
       const id = setTimeout(() => inputRef.current?.focus(), 100);
       return () => clearTimeout(id);
     }
   }, [isOpen, isMobile]);
   ```
   Это предотвращает клавиатуру при открытии поиска с мобильного (хотя SearchPanel -- отдельная панель, консистентность с TocSidebar fix важна).

   Примечание: если пользователь сам тапает на поле ввода -- клавиатура появится как ожидается. Автофокус убирается только при программном открытии панели.

**Сохранить:** Все callbacks (handleInputChange, handleKeyDown), nav buttons (ChevronUp/Down), close button (X), AnimatePresence анимация, dynamic top positioning.
  </action>
