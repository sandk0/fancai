# Дорожная карта: fancai Готовность к продакшену

## Обзор

fancai — это работающее AI-приложение для чтения книг, развернутое на fancai.ru на выделенном сервере (32GB RAM, 12 vCPU, PostgreSQL 17). Фазы 1-4.1 завершены: устранены уязвимости безопасности, удалён мёртвый код, все AI-сервисы мигрированы на OpenRouter, nginx заменён на Caddy, развёрнут мониторинг-стек, обновлены зависимости и выполнен полный ребрендинг bookreader -> fancai.

Оставшиеся фазы 5-8 фокусируются на качестве продукта: стабилизация AI-пайплайна и очистка остаточного техдолга, укрепление Entity Wiki (ключевого дифференциатора), полировка обработки ошибок и реализация функций ридера. Два из трёх требований AI-пайплайна (AI-01 семафор, AI-03 async) выполнены в ходе миграции OpenRouter (фаза 3), поэтому фаза 5 переориентирована на circuit breaker, резервное копирование БД и очистку остаточного техдолга, выявленного свежим аудитом кодовой базы.

### Phase 1: Безопасность продакшена

**Goal:** Приложение безопасно для работы в продакшене — нет эксплуатируемых уязвимостей, реальный мониторинг фиксирует ошибки, сервер работает в production-режиме с защитой данных, критические баги инфраструктуры устранены
**Depends on:** Ничего (первая фаза)
**Requirements**: SEC-01, SEC-02, SEC-03, DEPLOY-01, DEPLOY-02, DEPLOY-03, DEPLOY-05, DEPLOY-06, DEPLOY-07, DEPLOY-08, UX-01
**Критерии успеха** (что должно быть ИСТИННО):

1. Приложение запускается с DEBUG=False по умолчанию и отказывается стартовать, если в не-debug режиме используется SECRET_KEY по умолчанию
2. JWT-токены подписываются и верифицируются через PyJWT (не python-jose), поддельные токены с alg=none отклоняются
3. Health check endpoint возвращает реальный статус подключения к PostgreSQL, Redis и Celery (не захардкоженный "checking...")
4. Ошибки бэкенда отображаются в дашборде Hawk Tracker с полными стек-трейсами; JavaScript-ошибки фронтенда отображаются в отдельном проекте Hawk
5. Приложение работает под Gunicorn с UvicornWorker в продакшене (без флага --reload)
6. Celery visibility_timeout (14400) превышает time_limit (10800) — нет дублирования задач
7. LANGEXTRACT_MODEL синхронизирован во всех docker-compose файлах (gemini-3-flash-preview)
8. PostgreSQL образ обновлён до 17.9-alpine (CVE-2025-8715 CRITICAL, CVE-2025-1094 HIGH устранены)
9. Memory limits для Celery workers единообразны во всех конфигурациях

**Goal:** Entity Wiki — ключевой дифференциатор fancai — доказуемо защищена от спойлеров, точно обрабатывает русские имена и обрабатывает книги любого размера без тихой потери сущностей
**Depends on:** Phase 5
**Requirements**: WIKI-01, WIKI-02, WIKI-03, WIKI-04
**Критерии успеха** (что должно быть ИСТИННО):

1. Нечёткое сравнение русских имён использует пониженный порог (~0.70-0.75), чтобы короткие имена вроде «Гарри» корректно сопоставлялись с «Гарри Поттер» при дедупликации сущностей
2. Книги с 500+ сущностями полностью обрабатываются через рекурсивный map-reduce в ConsistencyManager вместо обрезки на 300K символах — никакой тихой потери сущностей

4. Спойлер-защищённая фильтрация имеет исчерпывающее тестовое покрытие, включая property-based тесты (Hypothesis), граничные случаи пограничных глав и сценарии пустых сущностей — никаких утечек данных из будущих глав
