# S05: Uat Edge Taps — UAT

**Milestone:** M003
**Written:** 2026-03-12

## UAT Type

- UAT mode: mixed
- Why this mode is sufficient: Unit-тесты проверяют логику (stale closure, CSS injection, edge zone detection). Ручное тестирование на устройстве необходимо для подтверждения UX (ложное выделение, непрозрачность фонов, отзывчивость аннотаций).

## Preconditions

- Frontend dev server запущен (`cd frontend && npm run dev`)
- Книга загружена в ридер с минимум 1 заметкой/выделением
- Устройство: мобильный или тач-экран (BUG-1, BUG-5 проявляются на touch)

## Smoke Test

Открыть книгу → тапнуть по тексту в центре → текст НЕ должен выделяться (BUG-1 fix)

## Test Cases

### 1. BUG-1: Простой тап не вызывает выделение текста

1. Открыть книгу на любой странице на мобильном устройстве
2. Тапнуть по тексту в любом месте (не long-press)
3. **Expected:** Текст не выделяется, страница перелистывается или header появляется/скрывается

### 2. BUG-2/3: Непрозрачный фон drawer-ов

1. Открыть книгу, тапнуть на выделенное описание (description highlight)
2. Посмотреть фон DescriptionDrawer
3. Тапнуть на entity-mention в тексте
4. Посмотреть фон EntityBottomSheet
5. **Expected:** Оба drawer-а имеют непрозрачный (solid) фон, текст книги не просвечивает. Проверить во всех 4 темах (light, dark, sepia, outdoor)

### 3. BUG-4: Аннотация отображается мгновенно после создания

1. Выделить текст long-press → создать заметку
2. **Expected:** Выделение визуально появляется сразу (не требует создания ещё одной заметки для "проявления")

### 4. BUG-5: Edge tap на description/entity у края экрана

1. Найти описание или entity-mention, расположенные у левого/правого края экрана (в edge zone ~15% viewport)
2. Тапнуть на элемент
3. **Expected:** Открывается соответствующий drawer (DescriptionDrawer или EntityBottomSheet), а не происходит перелистывание страницы

### 5. Long-press выделение текста по-прежнему работает

1. Long-press на тексте → drag для выделения
2. **Expected:** Текст выделяется, появляется SelectionMenu для создания заметки

## Edge Cases

### Description у самого края экрана

1. Найти описание, где текст начинается в первых 15% ширины экрана
2. Тапнуть на него
3. **Expected:** DescriptionDrawer открывается (elementFromPoint корректно определяет элемент)

### Быстрое создание нескольких заметок подряд

1. Создать заметку → сразу выделить другой текст → создать ещё заметку
2. **Expected:** Обе аннотации отображаются корректно (bookmarksRef не теряет данные при быстрых обновлениях)

### Переключение темы с открытым drawer

1. Открыть DescriptionDrawer → переключить тему (dark → sepia)
2. **Expected:** Фон drawer-а остаётся непрозрачным в новой теме

## Failure Signals

- Текст выделяется при простом тапе (BUG-1 не исправлен)
- Фон drawer-а полупрозрачный, текст книги виден позади (BUG-2/3 не исправлены)
- После создания заметки подсветка не появляется, требуется повторное действие (BUG-4 не исправлен)
- Тап на description/entity у края экрана вызывает перелистывание вместо открытия drawer (BUG-5 не исправлен)

## Requirements Proved By This UAT

- ENT-02 — edge tap entity/description test case #4 доказывает что тапы на интерактивные элементы у краёв экрана не перехватываются навигацией

## Not Proven By This UAT

- Реальное мобильное устройство с конкретными edge cases (маленький экран 320px, медленный тач-отклик)
- Офлайн-режим с аннотациями — bookmarksRef pattern не тестируется без сети
- Производительность debounce при сотнях аннотаций на одной странице

## Notes for Tester

- BUG-1 (ложное выделение) критичнее всего проверить на реальном iOS/Android — desktop-эмуляция тач-событий может не воспроизводить проблему
- При переключении тем обратить внимание на sepia и outdoor — light/dark обычно проблем не имеют
- Unit-тесты покрывают stale closure и debounce timing — ручной UAT фокусируется на visual/UX аспектах
