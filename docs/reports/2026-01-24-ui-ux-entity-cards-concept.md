# Концепция UI/UX: Карточки Сущностей и Система Анти-Спойлеров

**Дата:** 24.01.2026
**Статус:** Draft Concept
**Цель:** Разработать дизайн-систему для отображения персонажей и локаций, которая адаптируется под прогресс чтения и предотвращает спойлеры.

## 1. Философия: "Progressive Disclosure" (Поступательное Раскрытие)

Главный принцип UX системы `fancai` — **читатель должен знать только то, что знает главный герой на текущий момент**.

*   **Динамический Контент**: Одна и та же карточка "Геральт" выглядит по-разному в Главе 1 и в Главе 10.
*   **Spoiler Protection**: Информация из будущих глав (смерть, предательство, раскрытие тайны) физически недоступна или скрыта.

---

## 2. Сценарии Интерфейса (3 Views)

### А. In-Reader View (Контекстная Шторка)
*Сценарий: Читатель встречает имя "Зоррил" в тексте и тапает по нему.*

*   **Компонент**: Mobile Bottom Sheet (используем библиотеку `vaul` или `react-spring-bottom-sheet`).
*   **Состав**:
    *   **Header**: Имя + Мини-аватар (Avatar).
    *   **Snapshot**: Одно предложение, актуальное *на данный момент*.
        *   *Пример (Глава 1)*: "Неизвестное существо, похожее на ящера."
        *   *Пример (Глава 5)*: "Зоррил — опасный хищник, которого Геральт убил в шахте."
    *   **Action**: Кнопка "Открыть полное досье" (переход к Full Profile).
*   **Анти-Спойлер**:
    *   Если персонаж еще не встречен (в будущем), имя в тексте не подсвечивается.
    *   Связи показываются только те, что уже проявились в тексте.

### Б. Full Entity Profile (Полное Досье)
*Сценарий: Изучение персонажа из Галереи или Шторки.*

*   **Hero Section**:
    *   Большой портрет (Master Reference) с эффектом параллакса.
    *   **Blur Effect**: Если портрет спойлерит внешность (шрам, корона), он размыт до момента описания этого в тексте.
*   **Секция "Биография" (Progressive Lore)**:
    *   Текст формируется динамически. Абзацы из будущих глав скрыты плашкой `[Locked]`.
    *   **UX Pattern**: "Redacted Text" (Стиль секретных документов ЦРУ) — черные полосы поверх спойлерного текста, которые нельзя убрать.
*   **Секция "Связи"**:
    *   Список (List) персонажей с иконками отношений (Меч = Враг, Сердце = Любовь).
    *   **Strength=0 workaround**: Не рисуем граф с толщиной линий. Используем группировку: "Союзники", "Враги", "Семья".
*   **Секция "Хронология" (Timeline)**:
    *   Список сцен (описаний), которые пользователь *уже прочитал*.
    *   Сцены из будущего скрыты.

### В. Entity Gallery (Каст Книги)
*Сценарий: "Кто все эти люди?" (обзор перед чтением или в процессе).*

*   **Grid Layout**: Сетка карточек (как в Apple Books или Netflix Characters).
*   **States**:
    1.  **Unknown**: Силуэт + знак вопроса (персонаж есть в книге, но еще не встречен).
    2.  **Met**: Аватар + Имя.
    3.  **Dead**: Аватар серый + иконка черепа (если смерть уже произошла в `current_chapter`).
*   **Фильтры**: "Только встреченные", "Главные герои", "Локации".

## 3. Техническая Реализация (Frontend Stack)

### Libraries & Components
1.  **Компоненты (UI Kit)**:
    *   `shadcn/ui`: База (Cards, Badges, ScrollArea).
    *   `vaul`: Идеальный Drawer для мобильных (тянется, свайпается).
    *   `framer-motion`: Анимация появления ("Unlocking" effect).

### Архитектура Данных (Data Flow)
**Проблема**: Бэкенд сейчас отдает *полный* список описаний без привязки к главам (только `position_in_chapter` у Description).

**Решение на Фронте (или BFF)**:
1.  Загружаем `Full Entity` (со всеми спойлерами).
2.  Фронтенд знает `current_reading_chapter` (из LocalStorage/Reader state).
3.  **Filter Logic**:
    ```typescript
    const visibleDescriptions = entity.descriptions.filter(
      desc => desc.chapter_index <= currentChapterIndex
    );
    
    const isMet = visibleDescriptions.length > 0;
    
    // Если еще не встречен - показываем Locked State
    if (!isMet) return <LookedEntityCard />;
    ```

### Результаты Исследования (Browser Research Findings)
Мы провели анализ современных паттернов в мобильных играх и приложениях.

#### 1. In-Reader View: Bottom Sheet
**Рекомендация:** Использовать библиотеку **Vaul** (emilkowal.ski/vaul).
*   **Почему:** Это стандарт индустрии для React-приложений в 2025 году.
*   **Особенности:**
    *   Нативная инерция и жесты (как в iOS Maps).
    *   Поддержка "Snap points" (можно открыть шторку на 30% для краткой справки или потянуть выше для полного досье).
    *   Идеальная работа с мобильными клавиатурами.

#### 2. Визуализация Спойлеров (Spoiler UI Patterns)
Исследование ("TV Tropes Interface Spoiler", "Discord/Reddit patterns") показало два основных подхода:
*   **Blur (Размытие)**: Стандарт де-факто для медиа-контента (Discord). Самый "чистый" вариант для интерфейса.
*   **Redaction (Черный маркер)**: Стилизация под секретные документы (SCP Foundation, Control).
*   **Решение для Fancai**:
    *   **Для Портретов**: Strong Blur (Gaussian Blur 20px). Пользователь видит цвета, но не детали (например, корону на голове или шрам).
    *   **Для Текста**: Redaction Bar. Это создает атмосферу тайны и интригует сильнее, чем просто скрытый текст. Клик по плашке -> анимация "растврорения" чернил (если спойлер разрешен).

#### 3. Состояние "Unknown" в Галерее
Паттерн из RPG-игр (Bestiary/Codex):
*   **Силуэт (Silhouette)**: Вместо серой заглушки используется контур персонажа с эффектом `Inner Glow`.
*   **Геймификация**: Это мотивирует читателя "открыть" всех персонажей.

### Обработка "Мусорных" данных (Sanitization)
*   **Связи с силой 0**: Игнорируем поле `weight`. Сортируем просто по наличию.
*   **Дубликаты**: На клиенте делаем `deduplicateByName()` перед рендером Галереи.

## 4. Дизайн-Код (Visual Style)
*   **Glassmorphism**: Используем полупрозрачные подложки для текста поверх артов.
*   **Typography**: Serif для имен (атмосфера книги), Sans-serif для интерфейса.
*   **Colors**:
    *   Accent Color берется из обложки книги (или доминантного цвета аватара).
    *   Спойлеры: Темно-серый 900 (Redacted) или Blur.
