# Отчёт: Анализ зависания прогресса обработки книги

**Дата:** 22.01.2026  
**Статус:** ✅ Исправлено вручную на сервере  
**Книга:** "Ученик убийцы" (`3b17cafe-738a-40c6-93db-5dc25620e762`)

---

## Краткое описание проблемы

Frontend отображал 100% прогресс обработки книги, но overlay не закрывался. Книга оставалась в состоянии "обработка" бесконечно.

---

## Диагностика

### Проверка базы данных (Production)

```
Processing: True, Parsed: True, Progress: 100, Error: None
```

**Вывод:** Обработка завершена успешно (progress=100, is_parsed=True), но флаг `is_processing` не был сброшен в `False`.

### Проверка логов Celery

```log
WARNING | Book already being processed (lock exists)
INFO    | Task process_book[...] succeeded: {'status': 'skipped'}
```

**Вывод:** Новая задача была отправлена в очередь, но пропущена из-за существующего Redis lock.

---

## Причины

### 1. Прерывание воркера при деплое

При выполнении `docker compose up --build` контейнеры перезапускаются с `SIGKILL` (моментальное завершение). Celery воркер, обрабатывающий книгу, был убит **после** завершения обработки последней главы, но **до** финального коммита `is_processing=False`.

### 2. Redis Lock не освобождён

Redis lock (`book:processing:UUID`) имеет TTL 3 часа. При принудительном завершении воркера lock не освобождается, и новые задачи не могут взять книгу на обработку.

### 3. Отсутствие атомарности финального коммита

Функция `_process_book_async` устанавливает `is_processing=False` только в самом конце успешного пути. Если воркер прерван между обработкой последней главы и финальным коммитом, база данных остаётся в некорректном состоянии.

---

## Решение (ручное)

Выполнен скрипт `fix_async_book.py` на сервере:

```python
book.is_processing = False
await session.commit()
```

**Результат:** Overlay закрылся, книга отображается как "обработанная".

## Заключение

Проблема вызвана **race condition** между завершением обработки и перезапуском контейнеров при деплое. Рекомендуется реализовать graceful shutdown для Celery воркеров и улучшить атомарность финального коммита состояния книги.
