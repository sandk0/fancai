## 1. Современные практики iOS-разработки

### 1.1 Swift 6.0 / 6.2 — Что нового

#### Текущий статус

Swift 6.0 был выпущен в сентябре 2024, Swift 6.2 — в сентябре 2025. На январь 2026 актуальная версия — **Swift 6.2**, а на подходе Swift 6.3.

#### Ключевые возможности Swift 6.0

| Feature | Описание |
|---------|----------|
| **Data Race Safety** | Компилятор обнаруживает потенциальные data races как ошибки компиляции |
| **Typed Throws** | Функции могут указывать конкретный тип ошибки в сигнатуре |
| **128-bit Integers** | Знаковые и беззнаковые 128-битные целые числа |
| **Synchronization Library** | Низкоуровневые API для атомарных операций и mutex |
| **Embedded Swift** | Экспериментальная поддержка для embedded-устройств |

#### Ключевые возможности Swift 6.2 (WWDC 2025)

| Feature | Описание |
|---------|----------|
| **Approachable Concurrency** | Упрощенный подход к безопасному конкурентному коду |
| **@concurrent атрибут** | Явная маркировка кода для параллельного выполнения |
| **InlineArray** | Массивы фиксированного размера: `var arr: [50 of String]` |
| **Span** | Безопасная альтернатива buffer pointers |
| **WebAssembly Support** | Компиляция в Wasm через новый Wasm SDK |
| **Subprocess Package** | Async-friendly API для запуска внешних процессов |
| **Background Indexing** | Улучшенная производительность IDE |

#### Рекомендации

- **Начинайте миграцию на Swift 6** — с апреля 2025 все новые приложения должны собираться с Xcode 16 и iOS 18 SDK
- **Включайте strict concurrency checking постепенно** — сначала как warnings в Swift 5 mode
- **Используйте @MainActor по умолчанию** — Swift 6.2 позволяет изолировать код на главном потоке без явных аннотаций

#### Пример использования

```swift
// Swift 6.2: InlineArray
var buffer: [1024 of UInt8] = .init(repeating: 0)

// Swift 6.2: @concurrent для параллельного выполнения
@concurrent
func processData(_ data: Data) async -> Result {
    // Этот код может выполняться параллельно
}

// Swift 6: Typed throws
func loadConfig() throws(ConfigError) -> Config {
    // ...
}
```

### 1.2 SwiftUI iOS 17/18 — Готовность для Production

#### Текущий статус

SwiftUI в iOS 18 — **production-ready для большинства приложений**, но UIKit/AppKit остаются необходимыми для экстремальных требований производительности (браузеры, игры, креативные инструменты).

#### Новые возможности iOS 18

| Feature | Описание |
|---------|----------|
| **Improved Rendering Engine** | Более плавные анимации и transitions |
| **Better Memory Management** | Уменьшение вероятности memory leaks |
| **onScrollGeometryChange** | Расширенный контроль над scroll views |
| **Fine-grained Subview Control** | Публичный API для детального управления subviews |
| **Better Error Messages** | Более информативные сообщения об ошибках |
| **Improved UIKit Interop** | Упрощённая интеграция SwiftUI/UIKit |

#### Рекомендации для Reader App

- **SwiftUI подходит отлично**, но WebView придется оборачивать через UIViewRepresentable
- Стратегический подход: SwiftUI как основа, UIKit где нужна точная производительность
- Новые проекты: начинайте со SwiftUI, это предпочтительный путь от Apple

#### Пример для Reader App

```swift
struct ReaderView: View {
    @State private var currentPage = 0

    var body: some View {
        ScrollView {
            LazyVStack {
                ForEach(pages) { page in
                    PageView(page: page)
                        .containerRelativeFrame(.horizontal)
                }
            }
            .scrollTargetLayout()
        }
        .scrollTargetBehavior(.paging)
        .onScrollGeometryChange(for: Int.self) { geo in
            // iOS 18: отслеживание позиции скролла
            Int(geo.contentOffset.y / geo.containerSize.height)
        } action: { oldValue, newValue in
            currentPage = newValue
        }
    }
}
```

### 1.3 SwiftData vs Core Data — Что выбрать в 2026

#### Сравнительная таблица

| Критерий | SwiftData | Core Data |
|----------|-----------|-----------|
| **Минимальная iOS** | 17+ | 3.0+ |
| **Кривая обучения** | Часы | Недели |
| **Синтаксис** | Чистый Swift с макросами | NSManagedObject, verbose |
| **SwiftUI интеграция** | Нативная | Требует адаптеров |
| **Swift 6 Concurrency** | Поддерживается | Ограниченно |
| **Сложные relationships** | Базовая поддержка | Отличная |
| **Миграции** | Упрощенные | Мощный инструментарий |
| **Производительность** | Медленнее (пока) | Оптимизирован |
| **Зрелость документации** | Растёт | Огромная база |

#### Рекомендации по выбору

**Выбирайте SwiftData если:**
- Новый проект с iOS 17+
- Используете SwiftUI
- Простые-средние требования к данным
- Хотите быстрый старт

**Выбирайте Core Data если:**
- Существующий Core Data проект
- Сложные реляционные данные
- Enterprise/legacy приложения
- Нужны продвинутые миграции
- Поддержка iOS < 17

#### Пример SwiftData

```swift
import SwiftData

@Model
class Book {
    var title: String
    var author: String
    var currentPosition: String? // CFI for EPUB

    @Relationship(deleteRule: .cascade)
    var chapters: [Chapter] = []

    init(title: String, author: String) {
        self.title = title
        self.author = author
    }
}

// Использование в SwiftUI
struct BookListView: View {
    @Query(sort: \Book.title) private var books: [Book]
    @Environment(\.modelContext) private var context

    var body: some View {
        List(books) { book in
            Text(book.title)
        }
    }
}
```

### 1.4 Архитектурные паттерны

#### Текущий статус паттернов

| Паттерн | Популярность 2026 | Рекомендуемое применение |
|---------|-------------------|--------------------------|
| **MVVM** | Высокая | Средние-большие SwiftUI проекты |
| **MV (Model-View)** | Растущая | Небольшие-средние SwiftUI приложения |
| **TCA** | Высокая | SwiftUI-first apps, большие команды |
| **Clean Architecture** | Стабильная | Enterprise, сложные бизнес-требования |
| **VIPER** | Снижающаяся | Legacy, модульные enterprise-системы |
| **MVC** | Низкая | Прототипы, простые приложения |

#### MV Pattern (Model-View) — Новый от Apple

MV — паттерн, который Apple использует в своих SwiftUI-приложениях.

**Ключевая идея:** View в SwiftUI **уже является ViewModel** благодаря @State, @Observable, @Bindable.

```swift
// MV Pattern: View напрямую работает с Model
@Observable
class BookStore {
    var books: [Book] = []

    func loadBooks() async {
        books = await api.fetchBooks()
    }
}

struct BookListView: View {
    @State private var store = BookStore()

    var body: some View {
        List(store.books) { book in
            BookRow(book: book)
        }
        .task { await store.loadBooks() }
    }
}
```

#### TCA (The Composable Architecture)

TCA от Point-Free — мощный выбор для SwiftUI с unidirectional data flow.

```swift
@Reducer
struct BookListFeature {
    @ObservableState
    struct State {
        var books: [Book] = []
        var isLoading = false
    }

    enum Action {
        case loadBooks
        case booksLoaded([Book])
    }

    var body: some Reducer<State, Action> {
        Reduce { state, action in
            switch action {
            case .loadBooks:
                state.isLoading = true
                return .run { send in
                    let books = await fetchBooks()
                    await send(.booksLoaded(books))
                }
            case .booksLoaded(let books):
                state.books = books
                state.isLoading = false
                return .none
            }
        }
    }
}
```

#### Рекомендации по выбору архитектуры

| Размер проекта | Рекомендация |
|----------------|--------------|
| Прототип / MVP | MV или простой MVVM |
| Средний проект | MVVM с Dependency Injection |
| Большой проект | TCA или MVVM + Clean Architecture |
| Enterprise | Clean Architecture + модульность |

### 1.5 Async/Await и Concurrency — Best Practices

#### Ключевые принципы

| Принцип | Описание |
|---------|----------|
| **Используйте Tasks, не Threads** | Tasks — правильный примитив для 99% случаев |
| **Structured Concurrency** | async/await обеспечивает линейный, понятный код |
| **@MainActor для UI** | Гарантирует выполнение на главном потоке |
| **Actors для shared state** | Защита от data races |
| **Sendable для передачи между actors** | Compile-time проверка безопасности |

#### SwiftUI интеграция

```swift
struct ContentView: View {
    @State private var data: [Item] = []

    var body: some View {
        List(data) { item in
            ItemRow(item: item)
        }
        .task {
            // Автоматически отменяется при исчезновении view
            data = await loadData()
        }
        .refreshable {
            // Pull-to-refresh с async/await
            data = await loadData()
        }
    }
}
```

#### Actors для Thread Safety

```swift
actor ImageCache {
    private var cache: [URL: UIImage] = [:]

    func image(for url: URL) -> UIImage? {
        cache[url]
    }

    func store(_ image: UIImage, for url: URL) {
        cache[url] = image
    }
}
```

## 4. Консистентность AI-изображений

### 4.1 Обзор проблемы

При генерации AI-изображений персонажей для книг ключевая сложность — сохранение визуальной идентичности на протяжении всего произведения. Персонаж, созданный в первой главе, должен выглядеть так же в последней.

### 4.2 Технологии консистентности

#### IP-Adapter

- **Как работает:** Image Prompt Adapter от Tencent AI Lab — изображение как «визуальный промпт»
- **Качество:** Хорошее сохранение стиля, face fidelity средняя
- **Скорость:** ~2-5 секунд (inference only)

#### InstantID

- **Как работает:** Zero-shot метод с одного изображения, не требует fine-tuning
- **Качество:** Лучшее сохранение лицевой идентичности среди zero-shot методов
- **Скорость:** Генерация за секунды (tuning-free)
- **Ограничения:** Лицензия insightface — non-commercial

#### PuLID (Pure and Lightning ID)

- **Как работает:** ByteDance, решает проблему «model pollution»
- **Качество:** Восстановление >90% лицевых features, organic integration
- **Скорость:** Оптимизирован для rapid production
- **Стоимость:** $0.02/image на WaveSpeedAI

#### LoRA Training

- **Как работает:** Low-Rank Adaptation — fine-tuning части весов модели
- **Качество:** Наивысшая консистентность среди всех методов
- **Требования:** 20-25 изображений для качественного результата
- **Стоимость:** fal.ai: $2 за training run

### 4.5 Рекомендуемое решение для fancai

#### Архитектура хранения «seed» образов

```
characters/
├── {book_id}/
│   ├── {character_id}/
│   │   ├── reference_sheet.png      # Multi-view character sheet
│   │   ├── face_front.png           # Clean front face
│   │   ├── face_3quarter.png        # 3/4 angle
│   │   ├── full_body.png            # Full body reference
│   │   ├── lora_model.safetensors   # Trained LoRA (optional)
│   │   └── metadata.json            # Settings, prompts, seeds
```

#### Рекомендуемый pipeline для production

**Tier 1: Быстрый и дешёвый (большинство случаев)**
```
fal.ai FLUX + PuLID
├── Стоимость: $0.02-0.03/image
├── Скорость: <2 секунды
├── Консистентность: Высокая
└── Требования: 1 reference image
```

**Tier 2: Максимальная консистентность (главные персонажи)**
```
fal.ai FLUX LoRA Training
├── Training: $2 один раз
├── Inference: $0.02/image
├── Консистентность: Наивысшая
└── Требования: 20-25 качественных изображений
```

#### Trade-offs

| Фактор | PuLID (быстрый) | LoRA (качественный) |
|--------|-----------------|---------------------|
| Setup time | 0 | ~5 минут training |
| Per-image cost | $0.02 | $0.02 |
| Initial cost | $0 | $2 |
| Консистентность | 90% | 99% |
| Рекомендация | Второстепенные персонажи | Главные герои |
