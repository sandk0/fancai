# Рекомендации по оптимизации воркфлоу Claude Code для fancai

**На основе анализа:** 63 сессии | 7 182 вызова инструментов | 685 коммитов | 654 промпта
**Текущая конфигурация:** 3 skills, 3 agents, 3 commands, 1 hook, 88 permissions в settings.local.json
**Дата:** 05.02.2026

---

## Критические проблемы и решения

### 1. КРИТИЧНО: Снизить долю fix-коммитов (59% → <30%)

**Проблема:** 405 из 685 коммитов — исправления. Всего 5 test-коммитов (0.7%). Классический цикл «сделал → сломалось → чинил».

**Решение A — Stop-хук с проверкой тестов:**

Добавить хук, который при остановке Claude автоматически напомнит запустить тесты:

```json
// В .claude/settings.json → hooks
"Stop": [
  {
    "hooks": [
      {
        "type": "prompt",
        "prompt": "Перед завершением: убедись что запустил тесты (npm test / pytest -v) для всех изменённых файлов. Если тесты не запускались в этой сессии — запусти их сейчас."
      }
    ]
  }
]
```

**Решение B — Инструкция в CLAUDE.md:**

```markdown
## Обязательное тестирование

После ЛЮБОЙ правки кода:
1. Frontend: `cd frontend && npm test -- --watchAll=false`
2. Backend: `cd backend && pytest -v --tb=short`
Не коммить, если тесты падают. Если тестов нет — напиши их.
```

**Решение C — Активнее использовать TDD skill:**

У вас уже есть `/test-driven-development` из superpowers. Добавить в CLAUDE.md триггер:

```markdown
| "добавить", "реализовать", "создать", "новый" | `/test-driven-development` | Любой новый код |
```

### 2. КРИТИЧНО: Решить проблему сжатий контекста (97 за 641ч)

**Проблема:** Марафонские сессии (275ч, 180ч, 49ч) с многократным сжатием. При сжатии теряется контекст принятых решений.

**Решение A — SessionStart compact хук:**

Когда сессия возобновляется после сжатия, автоматически инжектировать контекст:

```json
// В .claude/settings.json → hooks
"SessionStart": [
  {
    "matcher": "compact",
    "hooks": [
      {
        "type": "prompt",
        "prompt": "Контекст после сжатия: Прочитай MEMORY.md проекта для восстановления ключевых решений текущей сессии. Затем проверь TodoWrite для текущего прогресса."
      }
    ]
  }
]
```

**Решение B — Инструкция в CLAUDE.md:**

```markdown
## Управление сессиями

- При 2-м сжатии контекста: предложи пользователю начать новую сессию с резюме
- Перед завершением длинной сессии: запиши прогресс в MEMORY.md
- Целевая длина сессии: 2-4 часа, одна задача
```

**Решение C — "Правило двойки":**

Если Claude дважды ошибся на одном и том же, лучше `/clear` и начать с нулевого контекста с улучшенным промптом, чем продолжать корректировать. Это напрямую адресует паттерн марафонских сессий.

## Важные улучшения

### 3. ВАЖНО: Создать MEMORY.md

**Проблема:** MEMORY.md отсутствует. Каждая сессия начинается с нуля — нет памяти о прошлых решениях, ошибках, паттернах.

**Рекомендация:** Создать начальный MEMORY.md на основе данных insights:

```markdown
# MEMORY.md

## Ключевые решения
- NLP система удалена (дек 2025), используется только Gemini 3.0 Flash
- EpubReader.tsx — самый горячий файл (84 изменения), нуждается в декомпозиции
- Деплой: ssh root@77.246.106.109 → docker-compose.lite.yml

## Частые ошибки
- docker-compose vs docker compose (используй docker compose)
- iOS Safari: всегда проверять touch-action и overscroll-behavior
- Gemini API: ответ может быть обёрнут в 'data' wrapper

## Архитектура
- Frontend: React 19 + epub.js 0.3.93 (CFI навигация критична)
- Backend: FastAPI + Celery (тяжёлые задачи) + PostgreSQL
- Описания: Dict-based (после удаления NLP)
```

---

### 4. ВАЖНО: Очистить settings.local.json

**Проблема:** 88 накопленных permission-записей, включая дубликаты и одноразовые команды (конкретные SSH-команды, конкретные git commit message).

**Рекомендация:** Заменить на чистый набор с вайлдкардами:

```json
{
  "permissions": {
    "allow": [
      "Bash(ssh:*)",
      "Bash(gh:*)",
      "Bash(wc:*)",
      "Bash(claude:*)",
      "WebSearch",
      "WebFetch(domain:github.com)",
      "WebFetch(domain:motion.dev)",
      "WebFetch(domain:www.anthropic.com)",
      "mcp__chrome-devtools__*",
      "mcp__plugin_context7_context7__*"
    ],
    "deny": [],
    "defaultMode": "acceptEdits"
  }
}
```

Базовые инструменты (npm, git, python, docker, Read, Edit, etc.) уже в `settings.json` — дублировать не нужно.

## Рекомендуемые улучшения

### 5. Добавить /deploy команду

**Проблема:** Деплой по SSH выполняется вручную с длинными командами. Одна из одобренных команд — 200+ символов SSH.

**Рекомендация:** Создать `.claude/commands/deploy.md`:

```markdown
Выполни деплой на продакшен сервер:
1. Убедись что все тесты проходят
2. Проверь что текущая ветка — main и всё закоммичено
3. git push origin main
4. ssh root@77.246.106.109 "cd /root/fancai-vibe-hackathon && git pull origin main && docker compose -f docker-compose.lite.yml build backend && docker compose -f docker-compose.lite.yml up -d backend"
5. Подожди 10 секунд, проверь docker compose ps
```

### 6. Оптимизировать промпт-паттерны

**На основе анализа:** 11 tool calls на промпт — высокая автономность. Но 59% fix говорит о неточных начальных инструкциях.

**Шаблоны для CLAUDE.md:**

```markdown
## Эффективные промпт-паттерны

### Для новой фичи:
"Добавь [что]. Затронутые файлы: [список]. Ожидаемое поведение: [описание].
Напиши тесты первыми (/test-driven-development)."

### Для бага:
"[Что] не работает. Ожидаемое: [X]. Фактическое: [Y]. Воспроизведение: [шаги].
Используй /systematic-debugging."

### Для рефакторинга:
"Рефакторинг [компонент]. Цель: [разделить/упростить/оптимизировать].
Ограничения: [что НЕ менять]. Составь план перед кодом."
```

**Принципы точного промптинга:**

| Стратегия | Плохо | Хорошо |
|-----------|-------|--------|
| Скоуп задачи | "добавь тесты для foo.py" | "напиши тест для foo.py, покрывающий edge case когда user не залогинен. без моков." |
| Указание источников | "почему у ExecutionFactory странный API?" | "посмотри git history ExecutionFactory и объясни как API эволюционировал" |
| Ссылка на паттерн | "добавь календарь-виджет" | "посмотри существующие виджеты (HotDogWidget.php — хороший пример), следуй паттерну для календаря" |
| Описание симптома | "исправь баг логина" | "логин падает после таймаута. проверь src/auth/, особенно token refresh. напиши falling test, потом фикси" |

### 8. Обновить CLAUDE.md — раздел дисциплины

Добавить в конец CLAUDE.md:

```markdown
## Рабочая дисциплина

### Тестирование
- После ЛЮБОЙ правки кода запускай релевантные тесты
- 0 fix-коммитов без предварительного теста
- Новый код = новые тесты (используй /test-driven-development)

### Сессии
- При 2-м сжатии контекста → предложи новую сессию с резюме
- Перед завершением → запиши прогресс в MEMORY.md
- Одна сессия = одна задача

### Коммиты
- Один коммит = одно логическое изменение
- Не коммить если тесты не прошли
- feat > fix: стремись к соотношению fix <30%

### EpubReader.tsx (84 изменения — самый горячий файл)
- Перед правкой: рассмотри выделение логики в отдельный хук/компонент
- Не добавляй новую логику в EpubReader.tsx напрямую без обоснования
```

### 9. Сократить CLAUDE.md

**Проблема:** CLAUDE.md (174 строки) на границе допустимого. Длинные файлы приводят к тому, что Claude игнорирует часть правил.

**Рекомендация:**

- Секцию Superpowers Auto-Routing (35 строк) вынести в отдельный skill `task-router` (уже частично реализован)
- Удалить секции, которые Claude может вывести из кода: API Quick Reference, Environment Variables
- Оставить только то, что Claude **не может** узнать из кода

**Принцип:** Если убрать правило и Claude всё равно ведёт себя правильно — удали его.
