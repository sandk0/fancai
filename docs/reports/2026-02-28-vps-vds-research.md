## 2. Требования проекта (сводка)

### Целевые характеристики сервера

| Параметр | Минимум                | Оптимум              | Обоснование                                            |
| -------- | ---------------------- | -------------------- | ------------------------------------------------------ |
| CPU      | 8 ядер (dedicated/KVM) | 10-12 ядер           | 6.2 CPU лимиты Docker + Sentry (2-3) + мониторинг (1)  |
| RAM      | 24 ГБ                  | 28-32 ГБ             | 7.8 ГБ сервисы + 6 ГБ Sentry + 2 ГБ мониторинг + запас |
| Диск     | 50 ГБ NVMe             | 80-100 ГБ NVMe       | Docker-образы + PostgreSQL + файлы + бэкапы + Sentry   |
| Порт     | 1 Гбит/с               | 1+ Гбит/с            | Нет CDN, EPUB + PNG раздаются с сервера                |
| DDoS     | L3/L4 включена         | L3-L7                | Базовая защита обязательна                             |
| Бюджет   | —                      | 7 000-10 000 руб/мес | Жёсткий потолок                                        |

### Критические технические требования

1. **NVMe** — PostgreSQL JSONB + Redis AOF + Docker overlay = высокий I/O
2. **KVM** — Docker требует полного ядра Linux (OpenVZ/LXC не подходят)
3. **Dedicated ядра** — AI-обработка книг загружает CPU на 100% при пиках
4. **Root-доступ** — Docker, UFW, crontab, sysctl, nginx
5. **Порт ≥ 1 Гбит/с** — без CDN все файлы раздаются с сервера (дисквалифицирующий фактор!)

### 4.7 Дисквалифицированные провайдеры

#### Beget (beget.com) — порт 250 Мбит/с

Отличный провайдер (SLA 99.98%, конфигуратор, отсутствие оверселлинга, дневная тарификация), но **порт 250 Мбит/с на всех тарифах** делает его непригодным для fancai без CDN. Рассмотреть, если в будущем подключить CDN.

Интересен двумя конфигураторами (Форсаж 4.0 + Атлант 3.0), хорошей поддержкой (15 мин ответ). Но **порт 100 Мбит/с** и скандал 2024 с повышением цен на уже оплаченные тарифы.

Лидер по инфраструктуре (20+ ДЦ, бункер с ФСТЭК, DDoS 1.5 Тбит/с). Но **два критических ограничения:** порт 100 Мбит/с и стандартные конфигурации ограничены 16 ГБ RAM.

Порт 200 Мбит/с, неясный тип виртуализации и дисков, CPU 2.4 ГГц, SLA не указан.

#### REG.RU — нет конфигуратора, мало RAM в бюджете

Фиксированные тарифы: 8 ядер = 16 ГБ RAM (8 000 руб), 24 ГБ RAM = 12 ядер (11 640 руб — за бюджетом). Конфигуратор отсутствует.

#### Fornex — нет серверов в РФ

Только Германия, Нидерланды, Швейцария, США, Испания.

## 9. Риски и рекомендации по миграции

### Риски при выборе провайдера

| Риск                 | Провайдер              | Вероятность         | Митигация                                  |
| -------------------- | ---------------------- | ------------------- | ------------------------------------------ |
| Повышение цен        | Все (тренд рынка)      | Высокая             | Оплата за год с фиксированной ценой        |
| DDoS-атака           | Timeweb (нет защиты)   | Средняя             | Подключить при первых атаках (550 руб/мес) |
| Деградация при пиках | VDSina (shared?)       | Средняя             | Timeweb: 100% guaranteed CPU               |
| Провайдер закрылся   | Aeza-подобный сценарий | Низкая (для зрелых) | Выбирать компании 10+ лет                  |
| Трафик > лимита      | Selectel (3 ТБ)        | Средняя             | Выбрать безлимитный (Timeweb)              |

### План миграции с текущего сервера

**Подготовка (1-2 дня):**

1. Заказать тестовый сервер у 1-2 финалистов (Timeweb: почасовой, AdminVPS: 7 дней бесплатно)
2. Задеплоить полный стек через docker-compose
3. Нагрузочное тестирование: обработка книги, параллельные запросы, Celery-задачи
4. Проверить дисковый I/O (PostgreSQL JSONB, Redis AOF)
5. Проверить скорость порта (iperf3)

**Миграция (2-4 часа даунтайма):**

1. Предупредить пользователей о плановом обслуживании
2. Остановить Celery workers, дождаться завершения задач
3. `pg_dump` → переносу на новый сервер → `pg_restore`
4. Скопировать файлы (EPUB, PNG): `rsync -avz`
5. Обновить DNS (A-запись fancai.ru) — TTL заранее снизить до 300 сек
6. Запустить docker-compose на новом сервере
7. Smoke-тесты: загрузка главной, авторизация, открытие книги, генерация иллюстрации
8. Мониторинг 24 часа

**Стратегия отката:**

- Старый сервер не удалять 7 дней
- DNS откат = 5 минут (TTL 300)
- pg_dump нового сервера перед удалением старого
