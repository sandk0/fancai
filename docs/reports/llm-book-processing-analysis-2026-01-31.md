## 1. Диагностика Проблем (Root Cause Analysis)

Мы провели аудит изменений за 20-31 января и выявили, что деградация качества — это результат конфликта между новой архитектурой (TSA, Structured Output) и старой логикой агрегации данных.

### 1.1. Почему "Мало описаний" и "Мало сущностей"?
**Причина:** Внедрение "Синдрома Вахтёра" в промпты.
*   **До рефакторинга:** Промпт просил "Выдели ВСЕ сущности".
*   **Сейчас (`gemini_extractor.py`):** Промпт жестко требует: *"Выдели ТОЛЬКО ГЛАВНЫХ (Top-15)... 1-6 ИГНОРИРОВАТЬ"*.
*   **Результат:** Модель Gemini 3, следуя инструкции, отбрасывает 90% "атмосферного" контента, который критически важен для world-building. Мы платим за мощную модель, но заставляем её работать как примитивный суммаризатор.

### 1.2. Почему "Visual Summary скудное и статичное"?
**Причина:** Логика "Wiper" (Стеклоочиститель) в `consistency_manager.py`.
*   **Код:** `if len(raw.visual_summary) > len(entity.visual_summary): entity.visual_summary = raw.visual_summary`
*   **Суть:** При слиянии данных из разных глав система просто оставляет *самое длинное* описание, удаляя предыдущее.
*   **Пример:** В Главе 1 герой в лохмотьях (длинное описание). В Главе 10 он в золотых доспехах (короткое описание). Система оставит "лохмотья" навсегда, так как текст длиннее. Эволюция персонажа уничтожается.

### 1.3. Почему "Карточки связей пустые"?
**Причина:** Блокировка обновления метаданных.
*   **Код:** В `_process_relationships` при нахождении существующей связи (`if existing:`) обновляется **только вес** (`weight`). Поле `context` (описание связи) **игнорируется**.
*   **Frontend Gap:** Компонент `RelationshipCard.tsx` жестко "зашит" (hardcoded) на 6 типов связей (`KINSHIP`, `ALLY`, `ENEMY`...). Если backend пришлет сложный тип (напр. `RIVALRY` или `ROMANCE`), фронтенд отобразит его как "HelpCircle" (иконка вопроса) и серый цвет.

### 1.4. Проблема Спойлеров
**Причина:** Глобальная дедупликация без учета времени.
*   **Механика:** Если модель понимает, что "Незнакомец в плаще" (Гл. 1) и "Король Артур" (Гл. 50) — это одно лицо, она сливает их в одну сущность ID=X.
*   **Баг:** У сущности ID=X есть список алиасов `["Незнакомец", "Король Артур"]`. Frontend получает весь список сразу. Читатель на 1-й главе видит спойлер "Король Артур" в карточке "Незнакомца".

## 2. Best Practices 2026 (Gemini 3 & Imagen 4)

### Gemini 3 Flash: Стратегия "Global Context"
*   **Lost in the Middle:** Gemini 3 имеет огромное окно (1M+), но внимание к середине текста может падать.
*   **Решение:** Использовать **"Paged Extraction"** с перекрытием. Не пытаться скормить всю книгу в один запрос, но и не дробить на мелкие чанки по 4000 символов (как сейчас). Оптимальный размер чанка для Gemini 3 — **50-100k токенов** (целая часть книги или 5-10 глав). Это позволяет модели видеть арки персонажей целиком.

### Imagen 4: Character Consistency
*   **Subject Reference:** Imagen 4 (через Vertex AI) поддерживает "Subject Reference" API — передачу набора изображений (3-5 шт) для фиксации внешности.
*   **Prompt Engineering:** Для сохранения стиля необходима формула: `[Style Anchor] + [Character Anchor] + [Scene Action]`.
    *   *Style Anchor:* "Cinematic shot, 35mm, anamorphic lens, Wes Anderson color palette".
    *   *Character Anchor:* "A ragged warrior with a scar across the left eye".

## 4. План Модернизации (Roadmap)

Мы отказываемся от "быстрых фиксов" в пользу фундаментальных улучшений.

### Phase 1: Расширение Промптов (Backend)
1.  **Снять ограничения:** Удалить `Top-15` и `Importance < 7`. Внедрить инструкцию "Extract EVERYTHING that matters".
2.  **Структурированное описание:** Заменить `visual_summary: str` на JSON-объект:
    ```json
    "appearance": { "face": "...", "body": "...", "clothing": "..." }
    ```
3.  **Богатые связи:** Внедрить новую таксономию в промпт. Требовать `context` в формате "Причина + Текущий статус".

### Phase 2: Динамический Граф (Architecture)
1.  **Entity Evolution:** Создать таблицу `EntityState` (`entity_id`, `chapter_range`, `visual_summary`, `status`). Это позволит показывать разное описание в начале и в конце книги.
2.  **Relationship History:** Хранить историю изменений связей.
3.  **Spoiler-Proofing:** Алиасы и факты должны иметь атрибут `reveal_chapter`. Frontend фильтрует их, если `current_chapter < reveal_chapter`.

### Phase 3: Frontend Adaptation
1.  **Smart Entity Card:** Карточка должна запрашивать данные: `getEntity(id, currentChapter)`. Backend возвращает состояние, актуальное именно для этой главы.
2.  **Dynamic Icons:** Обновить `RelationshipCard.tsx` для поддержки новой таксономии (иначе всё будет "HelpCircle").

## 5. The Omnibus Prompt (v3.0)

Этот промпт предназначен для `gemini_extractor.py` и решает проблемы скудности данных.

```python
OMNIBUS_EXTRACTION_PROMPT = """
Твоя роль: Ведущий Архивариус Мультивселенной и Арт-Директор.
Твоя цель: Создать исчерпывающую, глубокую базу знаний по тексту для RPG-игры и экранизации.

### 1. ГЛУБИНА АНАЛИЗА (NO FILTERS)
Не ограничивай себя "главными героями". Нам важен каждый трактирщик, каждый артефакт и каждая тень в углу, если они создают атмосферу.
Если персонаж появляется на одну сцену, но ярко описан — ИЗВЛЕКАЙ ЕГО.

### 2. ВИЗУАЛЬНЫЙ ПАСПОРТ (VISUAL SUMMARY)
Для Imagen 4 нам нужны детали, а не саммари.
*   **Плохо:** "Красивая девушка в платье."
*   **Хорошо:** "Молодая аристократка с бледной, почти прозрачной кожей. Высокий лоб, острые скулы. Носит тяжелое бархатное платье цвета свернувшейся крови с высоким кружевным воротником. На шее — серебряный медальон в форме змеи."

### 3. ДИНАМИКА СВЯЗЕЙ (RELATIONSHIPS)
Отношения меняются. Фиксируй нюансы.
*   Типы: [KINSHIP, ROMANCE, RIVALRY, ALLIANCE, HIERARCHY, NEMESIS].
*   Контекст: Обязательно укажи ПРИЧИНУ связи и ЭМОЦИОНАЛЬНЫЙ ОКРАС.
    *   *Пример:* "RIVALRY. Соперничают за внимание короля. Внешне вежливы, но строят козни."

### 4. ФОРМАТ JSON
{
  "entities": [
    {
      "name": "...",
      "type": "character",
      "visual_details": { ... }, 
      "importance": 1-10,
      "aliases": ["..."]
    }
  ],
  "relationships": [
    {
      "source": "...",
      "target": "...",
      "type": "RIVALRY",
      "context": "...",
      "quote": "..."
    }
  ]
}
"""
```
