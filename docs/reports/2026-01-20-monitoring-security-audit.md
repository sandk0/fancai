# Аудит Безопасности Мониторинга (2026)

Дата: 20 Января 2026
Статус: **КРИТИЧЕСКИЙ** (Требуются немедленные исправления)

## 🚨 Основные Угрозы и Уязвимости

### 1. Публичное раскрытие портов (Critical)
**Проблема:** В `docker-compose.monitoring.yml` все сервисы определены с секцией `ports`, которая по умолчанию в Docker привязывает порт ко всем интерфейсам (`0.0.0.0`).
- **Prometheus (:9090)**: Доступ не защищен (Basic Auth настроен только в Nginx, но порт 9090 открыт "мимо" Nginx). Любой может прочитать метрики или даже удалить их (через Admin API, если включен).
- **Loki (:3100)**: Доступ не защищен. Возможна утечка логов или инъекция фальшивых логов.
- **Node Exporter (:9100)**: Раскрывает детальную информацию о "железе" и ОС сервера.
- **cAdvisor (:8080)**: Раскрывает информацию о всех контейнерах.

**Риск:** Полная компрометация данных мониторинга, утечка информации об инфраструктуре, DoS атаки.
**Решение:** Убрать секцию `ports` для всех сервисов, доступ к которым нужен только через Nginx. Или привязать их строго к `127.0.0.1` (`127.0.0.1:9090:9090`).

### 2. Хранение секретов в Git (High)
**Проблема:** Файл `.htpasswd` (пусть и с хэшем) был добавлен в Git репозиторий.
**Риск:** При утечке хэша возможен брутфорс пароля. Нарушение принципа "Secrets Management".
**Решение:**
1. Удалить `.htpasswd` из репозитория.
2. Перегенерировать пароли.
3. Генерировать файл `.htpasswd` динамически при старте контейнера frontend, используя переменную окружения из `.env`.

### 3. Отсутствие шифрования внутреннего трафика (Medium)
**Проблема:** Трафик между Nginx и контейнерами мониторинга идет по HTTP.
**Контекст 2026:** Современные стандарты (Zero Trust) рекомендуют mTLS (Mutual TLS) даже внутри закрытого периметра.
**Решение:** Для данного масштаба проекта (Single Node) допустимо оставить HTTP внутри Docker сети, при условии, что внешние порты закрыты (см. пункт 1).

### 4. Привилегии контейнеров (Low/Medium)
**Проблема:** Некоторые контейнеры (например, Node Exporter, cAdvisor) требуют высоких привилегий.
**Решение:** Убедиться, что используются минимально необходимые `cap_add` и `security_opt` (уже частично сделано).

## 🛠 План исправлений (Remediation Plan)

### Этап 1: Закрытие внешнего периметра (НЕМЕДЛЕННО)
- [ ] Изменить `docker-compose.monitoring.yml`: Убрать `ports` для Prometheus, Loki, Node Exporter, cAdvisor (или настроить bind 127.0.0.1).
- [ ] Порт Grafana (3001) можно оставить на localhost, если доступ идет только через Nginx.

### Этап 2: Управление секретами
- [ ] Удалить `frontend/.htpasswd`.
- [ ] Добавить `frontend/.htpasswd` в `.gitignore`.
- [ ] Модифицировать `frontend/Dockerfile.prod`: Добавить скрипт `docker-entrypoint.sh`, который создает `.htpasswd` из переменной `BASIC_AUTH_PASSWORD`.
- [ ] Добавить переменную `BASIC_AUTH_PASSWORD` в `.env`.

### Этап 3: Hardening конфигурации
- [ ] Проверить, что Prometheus запущен с флагом `--web.enable-admin-api=false` (отключение опасных команд).
- [ ] Настроить Firewall (UFW) на сервере для блокировки всего, кроме 80, 443 и SSH.
