### 1.2 Почему LSP недоступен в кастомных агентах?

Согласно архитектуре Claude Code:

**Встроенные агенты** (Explore, Plan, general-purpose):
```
tools: "All tools" или "All tools except X, Y, Z"
```
LSP включён по умолчанию.

**Кастомные агенты** (epub-reader, gemini-imagen):
```yaml
tools:
  - Read
  - Edit
  - Write
  - Grep
  - Glob
  - mcp__context7...
```
Только **явно указанные** инструменты. LSP отсутствует = недоступен.

## 2. Анализ эффективности LSP

### 2.1 LSP vs другие инструменты

| Операция | LSP | Альтернатива | Когда LSP лучше |
|----------|-----|--------------|-----------------|
| **Структура файла** | `documentSymbol` | `Read` файла | Большие файлы (500+ строк) — LSP показывает структуру без чтения всего |
| **Поиск использований** | `findReferences` | `Grep` по имени | LSP понимает семантику (не найдёт "foo" в комментарии как использование) |
| **Навигация к определению** | `goToDefinition` | `Grep` + `Read` | LSP — один вызов вместо двух |
| **Информация о типе** | `hover` | `Read` определения | LSP показывает сигнатуру без навигации |
| **Call graph** | `incomingCalls`/`outgoingCalls` | Нет аналога | Уникальная возможность LSP |
| **Диагностика** | Автоматическая | Нет | LSP показывает ошибки при любой операции |

### 2.2 Сценарии для кастомных агентов

#### epub-reader
Работает с файлами:
- `EpubReader.tsx` (1200 строк)
- `useDescriptionHighlighting.ts` (900 строк)
- `useEpubLoader.ts` (750 строк)

**LSP был бы полезен для:**
- `documentSymbol` — обзор структуры больших файлов
- `findReferences` — найти все использования hook'а
- `hover` — понять типы props без чтения интерфейсов
- `incomingCalls` — понять, откуда вызывается функция

**Оценка:** ⭐⭐⭐⭐ (высокая полезность)

#### gemini-imagen
Работает с файлами:
- `gemini_extractor.py` (661 строк)
- `imagen_generator.py` (644 строк)
- `langextract_processor.py` (815 строк)

**LSP был бы полезен для:**
- `documentSymbol` — обзор классов и методов
- `findReferences` — найти все вызовы `extract()`
- `goToDefinition` — навигация к базовым классам
- `hover` — типы параметров

**Оценка:** ⭐⭐⭐⭐ (высокая полезность)

#### fancai-orchestrator
Роль: маршрутизация задач, не работает с кодом напрямую.

**LSP не нужен:** оркестратор делегирует работу специализированным агентам.

**Оценка:** ⭐ (не нужен)

## 3. Superpowers и LSP

### 3.1 Как работают superpowers

Superpowers skills — это **текстовые инструкции** (workflow guides), загружаемые через Skill tool. Они:

- Определяют **процесс** (шаги, checklist)
- НЕ определяют **инструменты** для основного агента
- Работают на уровне **основной сессии**

### 3.2 Доступность LSP в superpowers workflow

```
Пользователь → Skill tool → Загружает текст skill → Основной агент выполняет
                                                            ↓
                                                    LSP доступен ✅
```

**LSP уже доступен** при выполнении superpowers, т.к. основной агент имеет все инструменты.

### 3.3 Примеры

| Skill | Использует субагентов? | LSP доступен? |
|-------|----------------------|---------------|
| `systematic-debugging` | Нет | ✅ Основной агент |
| `test-driven-development` | Нет | ✅ Основной агент |
| `subagent-driven-development` | Да (general-purpose) | ✅ general-purpose имеет LSP |
| `brainstorming` | Нет | ✅ Основной агент |

**Вывод:** Superpowers НЕ требуют изменений.

## 4. Архитектурное ограничение

### 4.1 Почему LSP недоступен кастомным агентам?

LSP tool работает через плагины (vtsls, pyright), которые запускают language servers. Это **системный инструмент Claude Code**, а не обычный tool для субагентов.

**Структура LSP плагинов:**
```
~/.claude/plugins/cache/claude-code-lsps/
├── vtsls/0.1.0/
│   ├── plugin.json      # Метаданные плагина
│   └── .lsp.json        # Конфигурация language server
└── pyright/0.1.0/
    ├── plugin.json
    └── .lsp.json
```

### 4.2 Как определяются tools для агентов

**Встроенные агенты** (в системном промпте):
```
Explore: Tools: All tools except Task, ExitPlanMode, Edit, Write, NotebookEdit
general-purpose: Tools: *
```
LSP включён как часть "All tools".

**Кастомные агенты** (в .claude/agents/*.md):
```yaml
tools:
  - Read
  - Edit
  - Grep
  ...
```
Только явно указанные tools. LSP **не является** одним из доступных для указания tools.

### 4.3 Попытка добавить LSP (результат)

**Эксперимент:** Добавление `LSP` в tools кастомного агента.

```yaml
tools:
  - Read
  - Edit
  - LSP  # ← Добавлено
  - ...
```

**Результат:** LSP по-прежнему недоступен — Claude Code игнорирует неизвестные tools в конфигурации.

### 4.4 Вывод

**LSP нельзя добавить в кастомные агенты** — это ограничение архитектуры Claude Code.

## 5. Что НЕ нужно делать

### 5.1 Не изменять superpowers

Superpowers — текстовые инструкции. LSP уже доступен основному агенту при их выполнении.

### 5.2 Не изменять fancai-orchestrator

Оркестратор делегирует задачи, сам код не анализирует. LSP ему не нужен.

### 5.3 Не "приоритизировать" LSP глобально

LSP — это **дополнительный** инструмент, не замена. Правильный выбор инструмента зависит от задачи:

| Задача | Лучший инструмент |
|--------|-------------------|
| Прочитать содержимое файла | `Read` |
| Найти текстовый паттерн | `Grep` |
| Найти файлы по имени | `Glob` |
| Понять структуру кода | `LSP documentSymbol` |
| Найти семантические использования | `LSP findReferences` |
| Получить тип переменной | `LSP hover` |
| Навигация к определению | `LSP goToDefinition` |

## 6. Рекомендации по использованию LSP

### 6.1 Стратегия работы

Поскольку LSP недоступен кастомным агентам, рекомендую следующую стратегию:

| Задача | Рекомендуемый подход |
|--------|---------------------|
| **Анализ кода** (структура, зависимости) | Основной агент + LSP или Explore субагент |
| **Рефакторинг** (найти использования) | Основной агент + LSP findReferences |
| **Навигация** (определения, типы) | Основной агент + LSP hover/goToDefinition |
| **EPUB реализация** | epub-reader агент (без LSP, использует Read/Grep) |
| **AI сервисы реализация** | gemini-imagen агент (без LSP, использует Read/Grep) |

### 6.2 Когда использовать какой агент

```
┌─────────────────────────────────────────────────────────────┐
│                      ЗАДАЧА                                 │
└────────────────────────┬────────────────────────────────────┘
                         │
         ┌───────────────┴───────────────┐
         │                               │
    ┌────▼────┐                    ┌─────▼─────┐
    │ АНАЛИЗ  │                    │РЕАЛИЗАЦИЯ │
    │  КОДА   │                    │   КОДА    │
    └────┬────┘                    └─────┬─────┘
         │                               │
    ┌────▼────────────┐           ┌──────▼──────────┐
    │ Основной агент  │           │ Кастомный агент │
    │ или Explore     │           │ (epub-reader,   │
    │                 │           │  gemini-imagen) │
    │ ✅ LSP доступен │           │ ❌ LSP нет      │
    └─────────────────┘           └─────────────────┘
```

### 6.3 Практический workflow

**Для задач, требующих LSP:**
1. Выполняйте анализ в основной сессии (не делегируйте субагентам)
2. Или используйте Explore субагент для исследования

**Для задач реализации:**
1. Делегируйте специализированным агентам (epub-reader, gemini-imagen)
2. Они используют Read/Grep для навигации

### 6.4 Оптимальное использование кастомных агентов

Кастомные агенты эффективны для:
- Реализации конкретных фич в своей области
- Работы с Context7 MCP для документации библиотек
- Выполнения изменений (Edit/Write)

Для анализа кода перед делегацией используйте LSP в основной сессии.
