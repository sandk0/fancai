## Общая картина

**Что работает хорошо:** Вы построили высокопродуктивный цикл разработки full-stack приложения для чтения книг с ИИ-генерацией изображений. Массированное использование параллельных подагентов (514 вызовов Task) для мобильной адаптации и рефакторинга демонстрирует продвинутое владение Claude Code. Основной фокус правильно расставлен: фронтенд (56% файловых операций) с TypeScript/React — ядро пользовательского опыта.

**Что мешает:** Основной источник ошибок — Bash-команды (29 выходов с кодом 1, 16 не найденных команд). Высокая доля fix-коммитов (405 из 685 = 59%) говорит о цикле «реализовал — сломалось — чинил», характерном для быстрой итеративной разработки без предварительного тестирования. 97 сжатий контекста за 641 час работы указывает на длинные, тяжелые сессии, которые регулярно упираются в лимит контекста.

**Быстрые улучшения:** Разбивайте длинные сессии на более короткие с четкими целями. Используйте TDD-подход (skill `/test-driven-development`) для снижения доли fix-коммитов. Добавьте хуки для автоматического запуска тестов после правок.

## Где возникают проблемы

### Высокая доля fix-коммитов (59%)

405 из 685 коммитов — исправления. Это говорит о цикле «реализовал быстро — нашел баг — чинил». При всего 5 test-коммитах (0,7%) тестирование явно недостаточно.

**Рекомендация:** Используйте TDD-подход. Skill `/test-driven-development` уже доступен в вашем CLAUDE.md.

### Перегрузка контекста

97 сжатий контекста за 641 час. Самые длинные сессии: 275ч, 180ч, 49ч — фактически это «вечные» сессии с множественными сжатиями, где теряется контекст и Claude может забывать о ранее принятых решениях.

**Рекомендация:** Разбивайте работу на сессии по 2-4 часа с четким скоупом.

### Ночной цикл разработки

48,6% коммитов в ночное время (00-06 МСК). Усталость может приводить к менее точным промптам и менее внимательному ревью результатов Claude.

### Ошибки Bash-команд

87 ошибок связаны с Bash (exit code 1, 2, 127). Наиболее частые: `command not found` (docker-compose vs docker compose), неверные exit-коды при деплое.

## Ключевые паттерны использования

### Паттерн «Анализ — План — Армия агентов»

Типичная сессия: вы просите проанализировать проект/проблему, Claude создает TodoWrite-чеклист, затем запускает 3-6 параллельных подагентов для одновременного исправления. Это самый эффективный ваш паттерн.

### Паттерн «Марафонская сессия»

Длинные сессии (10+ часов) с многократным сжатием контекста. Работает для инкрементальных исправлений, но рискован для сложных задач, где важна целостность контекста.

### Паттерн «Деплой по команде»

Вы явно командуете «закоммить и задеплой на сервер» с указанием SSH и docker-compose конфигурации. Claude выполняет полный цикл: commit + push + ssh + deploy.

## Рекомендации для CLAUDE.md

### 1. Добавить ограничение на длину сессий

> При работе над крупной задачей, если происходит 3-е сжатие контекста, остановись и предложи пользователю начать новую сессию с резюме текущего прогресса.

### 2. Добавить обязательное тестирование

> После реализации любой фичи или исправления бага, всегда запускай `cd frontend && npm test` и `cd backend && pytest -v` для проверки регрессий. Не коммить, если тесты падают.

### 3. EpubReader декомпозиция

> EpubReader.tsx — самый горячий файл проекта (84 изменения). При следующем рефакторинге рассмотри разделение на более мелкие компоненты.
