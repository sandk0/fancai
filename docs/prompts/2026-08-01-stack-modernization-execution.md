### §2.1. Рабочее дерево грязное — прочитать до любого ветвления

На момент старта аудита в дереве было **29 изменённых файлов** (`+762/−336`) и
4 неотслеживаемых, **не относящихся к обновлению стека**. Это незакоммиченная работа
пользователя. §4 требует ветвиться от `main` — сделать это, не потеряв чужие правки,
можно только осознанно.

**Исходно грязный набор** (сверить перед началом):

```
 M .claude/hooks/protect-files.sh        M docs/README.md
 M .claude/settings.json                 M docs/architecture/ai-pipeline.md
 M .env.production.example               M docs/architecture/overview.md
 M .planning/PROJECT.md                  M docs/ci-cd/README.md
 M .planning/REQUIREMENTS.md             M docs/deployment/README.md
 M .planning/ROADMAP.md                  M docs/operations/README.md
 M .planning/STATE.md                    M docs/operations/migration/04-MIGRATION_RUNBOOK.md
 M .planning/codebase/ARCHITECTURE.md    M scripts/deploy-production.sh
 M .planning/codebase/CONCERNS.md        M scripts/deploy.sh
 M .planning/codebase/CONVENTIONS.md     M CHANGELOG.md
 M .planning/codebase/INTEGRATIONS.md    M CONTRIBUTING.md
 M .planning/codebase/STACK.md           M Caddyfile
 M .planning/codebase/STRUCTURE.md       M README-ru.md
 M .planning/codebase/TESTING.md         M README.md
 M docker-compose.prod.yml
?? docs/superpowers/plans/2026-07-18-production-reliability-baseline.md
?? scripts/migration-backup.sh
?? scripts/migration-restore.sh
?? v0_landing.pen
```

Контрольная сумма списка имён `M`-файлов: `8e7cba5267763e9da5800e3ca91c67fb`
(`git status --porcelain | grep '^ M' | awk '{print $2}' | md5sum`).

**Запрещено без явного разрешения пользователя:**

- `git reset --hard`, `git checkout -- .`, `git clean -fd`, `git stash` — любая из этих
  команд уничтожит или спрячет чужую работу;
- `git add -A`, `git add .`, `git commit -a` — затянут чужой diff в коммит волны;
- коммит любого файла из списка выше, **кроме двух исключений**: `Caddyfile` и
  `docker-compose.prod.yml` фиксируются пунктом 0.8 плана — и только если решение принято.

**Как ветвиться безопасно.** Незакоммиченные правки переносятся между ветками
автоматически, отдельных действий не требуется:

```bash
git status --porcelain > /tmp/fancai-dirty-before.txt   # зафиксировать исходное состояние
git switch -c chore/stack-wave-0                        # правки уедут в новую ветку сами
git add <перечислить файлы поимённо>                    # только свои, никогда -A
```

Перед мержем каждой волны сверять, что чужой набор не изменился:

```bash
diff <(git status --porcelain) /tmp/fancai-dirty-before.txt
```

Расхождение по файлам, которых ты не касался, — стоп и вопрос пользователю.
Если правки пользователя мешают (например, конфликт в `docker-compose.prod.yml`) —
не разрешать конфликт молча: зафиксировать и спросить.

## §3. Границы

**Входит:** исполнение Волн 0–6 по плану; минимальные правки совместимости; регенерация
lock-файлов; ведение `docs/progress.md` и `docs/handoff.md`.

**Не входит:**

| Не делать | Почему |
| --- | --- |
| Деплой, любые записи и рестарты на проде | жёсткая граница §12.2 исходного промпта; согласование плана ≠ разрешение трогать прод |
| Запуск чего-либо из `scripts/` | все скрипты трогают прод, `migration-restore.sh` разрушителен |
| Обновление документации под новые версии | отдельная задача; список — `docs/_drafts/2026-08-01-docs-impact-list.md` |
| Рефакторинг и чистка техдолга | `docs/_drafts/2026-08-01-tech-debt-backlog.md`; исключение — пункты, явно включённые в волны |
| Компоненты в статусе `HOLD` и `REPLACE` | у каждого зафиксировано условие снятия |
| Траты на платные API сверх smoke ≈ $0,90 | оценка в треке моделей §7 |

**Ловушка scope creep.** По ходу исполнения будет соблазнительно починить найденное рядом.
Не чини — дописывай в backlog.

## §4. Правила исполнения

- Одна волна — одна ветка от `main`; мерж только после зелёного критерия выхода.
  **Ветвление — строго по §2.1**: дерево грязное чужой работой, `reset`/`clean`/`stash`
  и `git add -A` запрещены, файлы в коммит перечисляются поимённо.
- Коммиты по `CONTRIBUTING.md`: `chore(deps):`, `build(docker):`, `ci:`, `feat(ai):`.
- **Атомарные группы не разделять**: 2.1 (fastapi + instrumentator), 3.2 (vite-plugin-pwa +
  все семь `workbox-*`), 4.2 (i18next + react-i18next). Порознь дерево не разрешится.
- **Правка `package.json` без регенерации lock — обновление на бумаге.** Чистая установка,
  новый lock в тот же коммит, повторный `npm audit`.
- Поломка внутри волны: чинить, если это совместимость. Если вскрылась архитектурная
  проблема — вернуть пакет в `HOLD`, записать в backlog, не втягиваться.
- Промежуточные проверки делать молча. Отчёт — по завершении волны, коротко.
- После каждой волны — запись в `docs/progress.md`; в конце сессии — обновить `docs/handoff.md`
  так, чтобы следующая стартовала без истории чата.

## §6. Критерии готовности

Проверяемые. «Сделано качественно» критерием не является.

- [ ] Каждая исполненная волна закрыта своим критерием выхода из плана.
- [ ] `cd backend && pytest -v` — список падений **не вырос** относительно до-среза.
- [ ] `cd frontend && npm test` — зелёный.
- [ ] `cd frontend && npm run lint && npm run type-check && npm run build` — чисто.
- [ ] `cd frontend && npm run build:size` — в бюджете 500 КБ на чанк / 800 КБ raw.
- [ ] `cd frontend && npm ci` проходит с нуля; lock перегенерирован и закоммичен.
- [ ] `docker build` обоих backend-образов проходит.
- [ ] `docker compose -f docker-compose.dev.yml up -d` — все сервисы healthy.
- [ ] Повторные `pip-audit` и `npm audit` сравнены с базовым срезом Фазы 0;
      ни одной **новой** находки High/Critical.
- [ ] Ручной smoke: загрузка книги → парсинг → извлечение сущностей → генерация изображения
      → чтение с подсветкой описаний.
- [ ] `docs/progress.md` содержит запись по каждой выполненной волне.
- [ ] `docs/handoff.md` обновлён, следующий шаг назван явно.
