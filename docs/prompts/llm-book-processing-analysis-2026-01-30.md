## Контекст задачи

Ты — старший системный аналитик, специализирующийся на реверс-инжиниринге сложных систем. Твоя задача — провести **исчерпывающий анализ** архитектуры и потоков данных системы обработки книг с использованием LLM (Large Language Models) в проекте **fancai**.

Проект fancai — это веб-приложение для чтения книг с автоматической генерацией иллюстраций на основе AI. Система использует Google Gemini для извлечения описаний и сущностей, Google Imagen для генерации изображений.

---

## Цель анализа

Мне необходимо получить **полное понимание всех процессов** "под капотом" — от момента загрузки книги до отображения сгенерированных изображений в читалке. Я не до конца понимаю текущий флоу и хочу:

1. Увидеть **детальную визуализацию** всех этапов обработки
2. Понять **какие компоненты участвуют** и как они взаимодействуют
3. Выявить **точки принятия решений** (условия, ветвления)
4. Определить **критические пути** и потенциальные узкие места
5. Сформировать базу для уточняющих замечаний по функциональности

## Методология анализа

### Шаг 1: Исследование точек входа

Найди и проанализируй:

1. **Frontend entry points:**
   - `BookUploadModal` — компонент загрузки
   - `useBooks` hook — API взаимодействие
   - Zustand stores — состояние загрузки

2. **Backend entry points:**
   - `POST /api/v1/books/upload` — endpoint загрузки
   - Celery task triggers — запуск фоновых задач

### Шаг 2: Трассировка Celery tasks

Проследи цепочку задач:

```
upload → process_book_task → ?
                           → parse_chapters?
                           → extract_descriptions?
                           → extract_entities?
                           → generate_portraits?
```

Для каждой задачи укажи:
- Имя функции и файл
- Что триггерит задачу
- Что задача делает
- Какие sub-tasks вызывает
- Какие данные записывает в БД
- Какие WebSocket события отправляет

### Шаг 3: Анализ LLM-интеграции

Детально опиши взаимодействие с Google Gemini:

- Какие промпты используются (system prompt, user prompt)
- Какая модель (`gemini-2.0-flash-exp`, `gemini-1.5-pro`, etc.)
- Как парсится ответ (Pydantic schemas)
- Как обрабатываются ошибки (retry, fallback)
- TSA (Trusted Safety API) — что это и как влияет

### Шаг 4: Анализ генерации изображений

Детально опиши взаимодействие с Google Imagen:

- Когда генерируются портреты персонажей vs изображения описаний
- Как формируются промпты для генерации
- Как сохраняются файлы (путь, формат)
- Как обновляется БД
- Seed — для чего используется

### Шаг 5: Анализ читалки

Проследи путь данных в читалке:

- `BookReaderPage` → какие hooks используются
- `useChapterData` → откуда берётся контент главы
- `useDescriptions` → как загружаются описания
- `DescriptionHighlighter` → как подсвечивается текст
- `EntityDrawer` → как отображаются персонажи
- `useReadingSession` → как трекается сессия чтения
