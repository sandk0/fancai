# Промпт для разработки системы "Сюжетные События" (Event Extraction)

**Роль:** Ты — Senior Software Architect и AI Engineer, специализирующийся на NLP и анализе художественных текстов. Ты проектируешь новую подсистему для проекта **fancai** (читалка книг с AI-обогащением).

**Контекст проекта:**
У нас есть бэкенд на Python (FastAPI + SQLAlchemy + PostgreSQL). Сейчас мы успешно извлекаем:
1.  **Сущности (Entities):** Персонажи, локации, предметы.
2.  **Визуальные описания (Visual Descriptions):** Фрагменты текста для генерации иллюстраций (Imagen 4).
3.  **Граф связей:** Кто с кем связан.

**Проблема:**
Текущие "Описания" слишком статичны и визуальны (например, "Мужчина в красном плаще"). Они не подходят для раздела "История персонажа". Пользователю интересно знать **сюжетные события** ("Спас принцессу", "Потерял меч", "Прибыл в замок"), а не то, как персонаж выглядел в каждой главе.

**Задача:**
Разработать архитектуру и промпты для новой сущности **"Сюжетное Событие" (Event)**.

**Требования к ответу:**

1.  **Проектирование БД (SQLAlchemy):**
    Предложи схему таблицы `events` и связующих таблиц.
    *   Какие поля нужны? (summary, type, importance, chapter_id, location_id?)
    *   Как связывать события с сущностями (участники)?
    *   Как хранить хронологию (порядок внутри главы)?

2.  **Промпт-инжиниринг (Gemini 1.5/2.0):**
    Напиши системный промпт (на русском языке) для извлечения событий из чанка текста книги.
    *   **Вход:** Текст главы (или чанк 50-100к токенов).
    *   **Выход:** JSON.
    *   **Критерии:**
        *   Отличать "Событие" (действие) от "Описания" (статика).
        *   Классифицировать типы: *Битва, Диалог, Путешествие, Откровение (Info), Смерть*.
        *   Определять "Важность" (1-10), чтобы фильтровать мелкие детали.
        *   Выделять участников (имена, как они указаны в тексте).

3.  **Алгоритм Дедупликации (Consistency):**
    Книга обрабатывается чанками. Одно событие может быть упомянуто на границе чанков или повторено в воспоминаниях.
    *   Как программно понять, что "Геральт убил грифона" в чанке А и "Битва с грифоном" в чанке Б — это одно и то же событие? Предложи эвристики (совпадение главы + участников + simhash?).

4.  **UX/UI Концепция (кратко):**
    Как лучше показать это пользователю в профиле персонажа?
    *   Таймлайн?
    *   Группировка по главам?
    *   Нужно ли показывать события, где персонаж был пассивным наблюдателем?

5.  **План внедрения:**
    Пошаговый план, как добавить это в существующий пайплайн (`GeminiDirectExtractor` -> `ConsistencyManager`), минимизируя лишние вызовы LLM (можно ли объединить с извлечением сущностей или нужен отдельный проход?).

**Вводные данные для анализа:**
*   Текущий стек: Python 3.11, Pydantic v2, SQLAlchemy 2.0 (Async).
*   LLM: Google Gemini 2.0 Flash (дешевая/быстрая) или Pro (умная).
*   Объем текста: Книги по 500+ страниц.
