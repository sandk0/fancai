**Отдельный контрольный прогон реального task-path.** Первые скрипты дёргали
`GeminiClient.generate_image()` напрямую и писали PNG в `/tmp`, поэтому строку
`generated_images.service_used='imagen'` они **не доказывали**: её создаёт только
`_generate_image_async()` в `image_tasks.py`. Прогон повторён внутри
`fancai_backend_dev` через `run_async(_generate_image_async(...))` — ровно то, что
вызывает Celery-таска, и на той же файловой системе `/app/storage`:

```
результат таски: success=True status=completed
generated_images: service_used='imagen' status='completed'
                  image_url=/api/v1/images/file/flux_20260801_100047_f670bad8.png
                  generation_time=12.46s
llm_usage_log:    gemini-3.1-flash-image service='image' $0.067 (на 16 мс раньше строки)
```

Проверка usage прицельная — по `service='image' AND model='gemini-3.1-flash-image'`,
а не по общему счётчику: `PromptTranslator` пишет свою строку с `service=NULL`
и замаскировал бы потерю именно той записи, ради которой чинилась долговечность.

**Первый прогон smoke вскрыл продовый дефект image path — исправлен и перепроверен.**
Скрипт просил `aspect_ratio="4:3"`, а получил 1408×768 (≈16:9):
`GeminiClient.generate_image()` принимал `aspect_ratio` и `image_size`, но собирал
`GenerateContentConfig` только с `response_modalities` и `types.ImageConfig`
не передавал. Это не артефакт скрипта: продовый путь
`ImagenService → NanoBananaGenerator` запрашивает ровно `4:3`/`1K`, то есть **все
иллюстрации читалки генерировались в чужом соотношении**. Дополнительно ломался
учёт: `compute_image_cost(model, image_size)` берёт **запрошенный** размер, поэтому
при любом не-дефолтном `image_size` в `llm_usage_log` попадала цена не того
разрешения. Ключ Redis-кэша картинок тоже включает `effective_aspect`, который
ни на что не влиял.

Параметры уходят в `image_config`; добавлен тест на собранный config (проверен
мутацией — на старом коде падает) и тест на отсутствие `temperature`.
Повторный smoke: `4:3` → **1200×896** (1,339), `16:9` → **1376×768** (1,792),
`1:1` + `2K` → **2048×2048** (4,0 Мпикс против 1,0 у 1K) — оба параметра работают,
а `compute_image_cost` снова соответствует фактическому разрешению.

**Потрачено около $0,63** при оценке $0,90 (восемь платных вызовов: два извлечения,
четыре генерации изображения на перепроверку геометрии и два прогона реального
task-path).

**Второй продовый дефект, найденный тем же прогоном: usage терялся под `asyncio.run`.**
Оба клиента писали `llm_usage_log` через `asyncio.create_task()`, а Celery-таски идут
через `run_async()` → `asyncio.run()`, который на выходе **отменяет незавершённые
задачи**. На коротких путях вроде генерации изображения запись не успевала выполниться
и терялась целиком. Первые smoke этого не показывали, потому что вручную делали
`gather` фоновых задач перед проверкой — то есть маскировали ровно тот эффект,
который отличает скрипт от продового рантайма.

Воспроизведено детерминированно (mock SDK + `asyncio.run`): 0 записей вместо 1.
Исправлено во всех пяти call sites — `gemini_client` (`_log` для текста и отдельная
ветка картинки) и `openrouter_client` (`generate_text`, `generate_structured`,
`generate_image`): вызов через `await`. Ошибки внутри по-прежнему проглатываются,
поэтому учёт не может уронить основной вызов.
Добавлен регрессионный тест под `asyncio.run`, проверенный мутацией.

**Оказалось не так, как ожидалось:**

1. **`llm_usage_log` молча не писался с хоста.** `_log_usage_to_db` глушит ошибки
   `warning`-ом, а SQLAlchemy async падал на `No module named 'greenlet'`: маркер
   пакета не ставит его на macOS `arm64`. Лечится установкой `greenlet` в локальный
   venv; попутно ожили 7 ранее падавших тестов.
2. **В dev брокер Celery живёт в Redis DB 0, а не в DB 1.** План предупреждал беречь
   DB 1 — локально всё наоборот: в DB 0 лежат `_kombu.binding.*`, а DB 1 пуста.
   `FLUSHDB` на DB 0 снёс бы очередь. Удаление сделано по шаблонам ключей.
3. **`docker-compose.dev.yml` не передаёт в контейнеры ни одной `GEMINI_*`/`GCP_*`
   переменной.** Первые smoke шли из host-venv; контрольный прогон task-path сделан
   `docker exec` с временно проброшенными ADC (файл и скрипт после прогона удалены
   из контейнера, наличие проверено `find`). После смены дефолта `AI_PROVIDER`
   на `gemini` dev-стек без ключей отключает `ImagenService` — видно в логах.
4. **Smoke оправдал себя не проверкой модели, а двумя продовыми находками** —
   геометрия изображения и потеря usage. Обе старше Волны 6. Unit-тесты их
   не ловили: проверяли тип возвращаемого значения и ветку safety-блокировки,
   но не собранный `GenerateContentConfig` и не поведение под `asyncio.run`.
5. **Прямой вызов клиента ≠ проверка пайплайна.** `service_used='imagen'` пишет
   только `_generate_image_async`, поэтому доказать критерий выхода можно было
   лишь прогоном настоящего task-path, а не вызовом `GeminiClient`.

### Волна 2 — backend

Атомарная группа fastapi 0.141.1 + instrumentator 8.1.0 подняла starlette
0.52.1 → 1.3.1 и закрыла 5 CVE. Обновлены пакеты безопасности, сервер, ORM,

**Оказалось не так, как ожидалось:**

1. **Starlette ≥ 1.0 запрещает `add_middleware` после старта.**
   `Instrumentator().instrument(app)` жил в lifespan и падал с `RuntimeError`,
   а ошибку глушил `try/except` — метрики исчезли бы молча. Вызов перенесён
   на уровень модуля, `try/except` убран. Проверено: `http_requests_total`
   растёт на реальных запросах, в контейнере 57 серий `http_*`.
2. **`app.routes` в starlette 1.x не разворачивает вложенные роутеры** — 118
   записей превратились в 21. Регрессии нет: множество путей в `openapi.json`
   совпадает — 103 и до, и после.
3. **ruff 0.16 расширил набор правил по умолчанию** (YTT, UP, B, BLE, I, RUF):
   1833 ошибки на неизменном коде. Добавлен `backend/ruff.toml`, фиксирующий
   прежний набор E4/E7/E9/F явно.
4. **Латентный баг, вскрытый удалением Modal.** В `backend/app/tasks/image_tasks.py` блок
   push-уведомления на OpenRouter-пути использовал `Chapter` и
   `push_notification_service`, которые импортировались только внутри
   Modal-ветки. На продовом пути это давало `NameError`, проглатываемый
   `except Exception`, — push молча не отправлялся.
5. **`modal_error` был бакетом «неизвестная ошибка»**, а не ошибкой Modal.
   После cutover он помечал бы так любую ошибку Gemini. Классификатор сделан
   провайдер-нейтральным (`provider_error`), исторические строки
   `chapters.error_type` переписывает миграция `c7d8e9f0a1b2`.
6. **`FeatureFlagManager.initialize()` только добавляет флаги.** Удаление
   `USE_MODAL_PIPELINE` и `USE_BATCH_MODE` из кода оставило бы в развёрнутых
