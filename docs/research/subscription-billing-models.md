## 2. Сравнение моделей биллинга для AI SaaS

### 2.1 Модели монетизации

#### A. Чистая подписка (Flat Subscription)

**Описание:** Фиксированная месячная плата, внутри — определённый набор лимитов.

| Плюсы                     | Минусы                                    |
| ------------------------- | ----------------------------------------- |
| Предсказуемый доход (MRR) | Тяжёлые пользователи убыточны             |
| Простота для пользователя | Нужно угадать лимиты                      |
| Низкий барьер входа       | Лёгкие пользователи переплачивают → churn |
| Простая реализация        | Эрозия маржи при росте AI-затрат          |

**Подходит для:** Продуктов с предсказуемым потреблением AI. **НЕ подходит** при высокой дисперсии usage (как у fancai — кто-то читает 1 книгу/мес, кто-то 10).

#### B. Оплата за использование (Pay-per-Use / Credits)

**Описание:** Пользователь покупает кредиты, каждая AI-операция списывает определённое количество.

| Плюсы                              | Минусы                                  |
| ---------------------------------- | --------------------------------------- |
| Справедливая цена = больше доверия | Непредсказуемый доход                   |
| Нет убыточных heavy users          | Трение при каждом действии (anxiety)    |
| Маржа защищена                     | Сложность UX — страх потратить кредиты  |
| Масштабируется с usage             | Холодный старт — нужно купить до начала |

**Подходит для:** API-продуктов, профессиональных инструментов. Для потребительского приложения — слишком много friction.

#### C. Гибрид: подписка + кредиты сверху (рекомендуется для fancai)

**Описание:** Базовая подписка включает N кредитов/месяц. Сверх лимита — докупка пакетов.

| Плюсы                                       | Минусы                  |
| ------------------------------------------- | ----------------------- |
| Предсказуемый базовый MRR                   | Сложнее реализовать     |
| Heavy users платят больше                   | Нужно объяснить систему |
| Нет anxiety — базовый лимит покрывает 80%   | Два типа транзакций     |
| Upsell natural: кончились кредиты → upgrade |                         |

**Это доминирующая модель в 2025–2026.** 85% SaaS компаний используют элементы usage-based pricing. Гибридные модели показывают +21% медианного роста по сравнению с чистыми моделями.

#### D. Freemium с AI-кредитами

**Описание:** Бесплатный тариф с ограниченным числом AI-операций. Paid — больше кредитов.

| Плюсы                      | Минусы                        |
| -------------------------- | ----------------------------- |
| Максимальная воронка       | Затраты на free users         |
| Viral growth               | Сложность удержания конверсии |
| Попробовать перед покупкой | Абузеры free tier             |

**Подходит для fancai** как стартовая воронка — дать попробовать AI на 1–2 книгах.

#### E. BYOK (Bring Your Own Key)

**Описание:** Power users подключают свой OpenRouter API ключ, приложение работает через него.

| Плюсы                            | Минусы                              |
| -------------------------------- | ----------------------------------- |
| Нулевые AI-затраты               | Сложность для обычных пользователей |
| Привлекает техническую аудиторию | Нет revenue от AI usage             |
| Снижает pressure на маржу        | Проблемы с поддержкой (чужой ключ)  |
| Хорош как top-tier фича          | Нет контроля за расходами           |

**Рекомендация:** BYOK как фича высшего тарифа или отдельная опция. Даёт power users полный контроль и снимает с нас AI-затраты. Реализация: пользователь вводит свой `OPENROUTER_API_KEY`, backend маршрутизирует вызовы через него.

## 3. Анализ реальных примеров

### 3.1 Midjourney — подписка + GPU-часы

| План     | Цена/мес | Fast Hours | Relax Mode   | Доп. Fast |
| -------- | -------- | ---------- | ------------ | --------- |
| Basic    | $10      | 3.3 ч      | Нет          | $4/час    |
| Standard | $30      | 15 ч       | Да (безлим.) | $4/час    |
| Pro      | $60      | 30 ч       | Да (безлим.) | $4/час    |
| Mega     | $120     | 60 ч       | Да (безлим.) | $4/час    |

**Ключевые решения:**

- Кредиты НЕ переносятся на следующий месяц
- Relax Mode — гениальное решение: безлимитная генерация в низком приоритете (очередь)
- Upsell через скорость, не через доступ

**Применимо к fancai:** Аналог Relax Mode — обработка книг в фоновой очереди Celery с низким приоритетом для free/базовых тарифов. Premium — приоритетная очередь.

### 3.2 ChatGPT — подписка с bundled AI

| План | Цена/мес | AI-лимиты                                 |
| ---- | -------- | ----------------------------------------- |
| Free | $0       | GPT-4o mini, ограниченные сообщения       |
| Plus | $20      | GPT-4o, DALL-E 3, расширенные лимиты      |
| Pro  | $200     | Безлимитный GPT-4o, o1, advanced features |

**Ключевые решения:**

- Нет явной кредитной системы — лимиты «мягкие» (rate limiting)
- Free tier даёт попробовать, но с ограничениями модели
- 10x разница между Plus и Pro — decoy pricing

### 3.3 Grammarly — freemium + AI upsell

| План       | Цена/мес         | AI-фичи                               |
| ---------- | ---------------- | ------------------------------------- |
| Free       | $0               | Базовая грамматика, тон               |
| Pro        | $12/мес (annual) | 2000 AI-промптов/мес, рерайт, плагиат |
| Business   | $15/мес/чел      | Командные фичи + AI                   |
| Enterprise | Custom           | Кастом                                |

**Ключевые решения:**

- Free tier — полноценный продукт (грамматика), AI — upsell
- 2000 AI-промптов/мес — щедрый лимит, не создаёт anxiety
- Годовая подписка 2.5x дешевле месячной — lock-in

**Применимо к fancai:** Базовая читалка бесплатна, AI-фичи — upsell. Это идеальная модель.

### 3.4 Notion AI — bundled в подписку + credits add-on

| Аспект              | Детали                                         |
| ------------------- | ---------------------------------------------- |
| Free/Plus           | 20 одноразовых AI-ответов (не обновляются)     |
| Business/Enterprise | AI включён безлимитно                          |
| Credits add-on      | $10 за 1000 Notion credits (для Custom Agents) |
| Rollover            | Кредиты НЕ переносятся, сброс каждый месяц     |

**Ключевые решения:**

- С мая 2025 AI убран из дешёвых тарифов — только Business+
- Кредитная система только для автоматизации (Custom Agents), не для базового AI
- Кредиты — workspace-level, не per-user

### 3.5 Character.ai — freemium + premium access

| План  | Цена/мес | Отличия                                                      |
| ----- | -------- | ------------------------------------------------------------ |
| Free  | $0       | Безлим. чаты, базовые модели, реклама                        |
| c.ai+ | $9.99    | Продвинутые модели, голосовые звонки, без рекламы, приоритет |

**Ключевые решения:**

- Free tier очень щедрый (безлим. чаты)
- Premium = качество модели + скорость + эксклюзивные фичи
- Нет кредитной системы — упрощённая монетизация

**Применимо к fancai:** Модель «бесплатно с базовыми фичами, premium за качество» хорошо работает для потребительских приложений.

### 3.6 Jasper AI — seat-based + credits

| План     | Цена/мес | Модель                    |
| -------- | -------- | ------------------------- |
| Creator  | $39      | 1 seat, безлим. слова     |
| Pro      | $59      | До 5 seats, безлим. слова |
| Business | Custom   | Custom seats + features   |

**Ключевые решения:**

- Перешли от word-based credits к безлимитным словам
- Кредиты остались только для специфичных фич (plagiarism check)
- Переход от credits к unlimited — сигнал рынка о том, что credits создают friction

## 4. Проектирование кредитной системы

### 4.1 Единая валюта: «Звёзды» (Stars / Кредиты)

Вместо раздельного учёта «глав» и «изображений» — единая внутренняя валюта.

**Почему единая валюта:**

- Проще объяснить пользователю
- Гибкость расходования (хочешь — на картинки, хочешь — на entities)
- Проще маркетинг и ценообразование
- Один баланс вместо нескольких счётчиков

### 4.2 Конвертация AI-операций в кредиты

Базовая единица: **1 кредит = 1 руб. себестоимости AI** (при текущем курсе ~$0.012).

| Операция                   | Себестоимость | Кредитов за операцию | Расшифровка             |
| -------------------------- | ------------- | -------------------- | ----------------------- |
| Анализ главы (entities)    | ~$0.04 (ср.)  | **5 кредитов**       | ~3.3 руб. себестоимости |
| Генерация изображения      | ~$0.014       | **2 кредита**        | ~1.2 руб. себестоимости |
| Синтез entities (за книгу) | ~$0.02        | **3 кредита**        | ~1.7 руб. себестоимости |
| Перевод промпта            | ~$0.001       | **0 кредитов**       | Включено в генерацию    |

**Стоимость типичной книги в кредитах:**

| Сценарий         | Entities (35 глав) | Картинки (35) | Синтез | Итого            |
| ---------------- | ------------------ | ------------- | ------ | ---------------- |
| Полная обработка | 175                | 70            | 3      | **248 кредитов** |
| Только entities  | 175                | 0             | 3      | **178 кредитов** |
| Только картинки  | 0                  | 70            | 0      | **70 кредитов**  |

### 4.3 Жизненный цикл кредитов

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│   Получение   │     │  Потребление  │     │   Истечение   │
│              │     │              │     │              │
│ • Подписка   │────▶│ • AI-вызов   │     │ • 90 дней    │
│ • Покупка    │     │ • Списание   │────▶│ • Неиспольз. │
│ • Бонус      │     │ • Отмена(?)  │     │ • FIFO       │
│ • Реферал    │     │              │     │              │
└──────────────┘     └──────────────┘     └──────────────┘
```

### 4.4 Правила кредитной системы

| Правило               | Решение                                               | Обоснование                                              |
| --------------------- | ----------------------------------------------------- | -------------------------------------------------------- |
| Rollover              | Подписочные кредиты — rollover до 2x месячного лимита | Не наказываем за неиспользование, но не копим бесконечно |
| Купленные кредиты     | Срок жизни 12 месяцев                                 | Бухгалтерия: кредиты — обязательство (liability)         |
| Бонусные кредиты      | Срок жизни 30 дней                                    | Стимулируют быстрое использование                        |
| Порядок списания      | FIFO: бонусные → подписочные → купленные              | Сначала тратим то, что сгорит раньше                     |
| Возврат при ошибке AI | Автоматический возврат кредитов                       | Пользователь не должен платить за наши баги              |
| Минимальная покупка   | 50 кредитов (~100 руб.)                               | Снижаем комиссию платёжной системы                       |

### 4.5 Отображение кредитов пользователю

**Принципы UX:**

1. **Баланс всегда виден** — в header/sidebar приложения
2. **Прозрачность перед списанием** — «Обработка главы: ~5 кредитов. Продолжить?»
3. **Предупреждение о низком балансе** — уведомление при < 20% от месячного лимита
4. **История расходов** — лог операций с деталями (дата, тип, книга, кредиты)
5. **Прогноз** — «При текущем темпе кредитов хватит на ~12 дней»

**Антипаттерн: НЕ показывать доллары.** Показываем только кредиты. Доллары создают негативную ассоциацию с расходами. Кредиты — геймифицированная валюта, воспринимаются легче.

### 4.6 Бонусы и реферальная программа

| Действие                        | Бонус                           | Срок жизни      |
| ------------------------------- | ------------------------------- | --------------- |
| Регистрация                     | 50 кредитов (≈1 книга entities) | 30 дней         |
| Реферал (пригласил друга)       | 100 кредитов обоим              | 30 дней         |
| Первая книга обработана         | 20 кредитов                     | 30 дней         |
| Отзыв в App Store / Play Market | 30 кредитов                     | 30 дней         |
| Подписка на годовой план        | +1 месяц кредитов               | Как подписочные |

## 5. Тарифные планы для fancai

### 5.1 Рекомендуемая структура: 4 тарифа

```
┌─────────────┬─────────────┬─────────────┬─────────────┐
│    FREE     │   ЧИТАТЕЛЬ  │  КНИГОЧЕЙ   │  БИБЛИОТЕКА │
│   (Старт)   │  (Starter)  │    (Pro)    │  (Ultimate) │
│             │             │             │             │
│   0 руб.    │  199 руб.   │  499 руб.   │  999 руб.   │
│             │    /мес     │    /мес     │    /мес     │
│             │             │             │             │
│  50 кредитов│ 300 кредитов│ 800 кредитов│   BYOK /    │
│  однократно │    /мес     │    /мес     │  безлимит   │
└─────────────┴─────────────┴─────────────┴─────────────┘
```

### 5.2 Детальное описание тарифов

#### FREE (Бесплатный)

| Параметр    | Значение                                   |
| ----------- | ------------------------------------------ |
| Кредиты     | 50 однократно (при регистрации)            |
| Книги       | Безлимитное чтение (без AI)                |
| AI Entities | Только на начальные кредиты (~1 книга)     |
| AI Картинки | Только на начальные кредиты (~25 картинок) |
| Хранилище   | 5 книг                                     |
| Обработка   | Низкий приоритет (очередь Celery)          |
| Оффлайн     | Да (IndexedDB кэш)                         |
| Реклама     | Нет (но баннер upgrade)                    |

**Цель:** Дать попробовать AI-фичи на одной книге. Конвертировать в платный тариф после того, как пользователь оценит entity glossary.

#### ЧИТАТЕЛЬ (Starter) — 199 руб./мес

| Параметр         | Значение                     |
| ---------------- | ---------------------------- |
| Кредиты          | 300/мес (rollover до 600)    |
| Книги            | Безлимитное чтение           |
| AI Entities      | ~60 глав/мес (~1–2 книги)    |
| AI Картинки      | ~150 картинок/мес            |

**Реализация:** Redis (DB 0) sliding window counter.

```python
# Пример: Rate limiting через Redis
async def check_rate_limit(user_id: str, action: str, limit: int, window: int) -> bool:
    key = f"rate:{action}:{user_id}"
    current = await redis.incr(key)
    if current == 1:
        await redis.expire(key, window)
    return current <= limit
```

## 8. Моделирование выручки

### 8.1 Unit economics одного пользователя

**Предположения:**

- Средний пользователь: тариф «Книгочей» (499 руб./мес)
- Обрабатывает ~3 книги/мес (средний роман, 35 глав)
- Генерирует ~50 картинок/мес
- Churn rate: 8%/мес (consumer app)

| Метрика                 | Значение                              |
| ----------------------- | ------------------------------------- |
| ARPU (мес.)             | 499 руб. (~$5.90)                     |
| AI себестоимость/мес    | ~$4.50 (3 книги entity + 50 картинок) |
| Инфраструктура/мес      | ~$0.30 (доля серверов на юзера)       |
| Платёжная комиссия (3%) | ~$0.18                                |
| **Gross profit/мес**    | **~$0.92 (15.6%)**                    |
| Lifetime (при churn 8%) | 12.5 мес.                             |
| **LTV**                 | **~$73.75 (≈6 240 руб.)**             |
| Gross LTV               | **~$11.50 (≈975 руб.)**               |

**Проблема:** Маржинальность очень тонкая при тарифе 499 руб. и активном использовании. Необходимо:

1. Часть пользователей не использует все кредиты (breakage ~30–40%)
2. Докупки кредитов добавляют ~15% к ARPU
3. Годовые подписки улучшают LTV и снижают churn

### 8.2 Сценарии breakage (неиспользованные кредиты)

«Breakage» — процент кредитов, которые пользователи получают, но не тратят. Это чистая прибыль.

| Сценарий             | Breakage | Эффект на маржу |
| -------------------- | -------- | --------------- |
| Активный читатель    | 10%      | +$0.45/мес      |
| Обычный пользователь | 35%      | +$1.57/мес      |
| «Подписался и забыл» | 80%      | +$3.60/мес      |
| Средневзвешенное     | **40%**  | **+$1.80/мес**  |

С учётом breakage 40%:

| Метрика              | Без breakage | С breakage 40% |
| -------------------- | ------------ | -------------- |
| AI себестоимость/мес | $4.50        | $2.70          |
| Gross profit/мес     | $0.92        | $2.72          |
| **Gross margin**     | **15.6%**    | **46.1%**      |

### 8.3 Когортная модель: первый год

**Предположения:** 100 новых пользователей/мес, конверсия free→paid 5%, распределение по тарифам.

| Месяц | Free users | Paid users | MRR (руб.) | AI costs | Gross Profit |
| ----- | ---------- | ---------- | ---------- | -------- | ------------ |
| 1     | 95         | 5          | 1 995      | 810      | 1 185        |
| 3     | 270        | 14         | 5 586      | 2 268    | 3 318        |
| 6     | 510        | 26         | 10 374     | 4 212    | 6 162        |
| 12    | 900        | 45         | 17 955     | 7 290    | 10 665       |

_При 5% конверсии, churn 8%/мес для paid, 15%/мес для free, breakage 40%, ARPU ~399 руб. (средний по тарифам)_

### 8.4 Break-even анализ

| Статья расходов         | Ежемесячно       | Примечание    |
| ----------------------- | ---------------- | ------------- |
| Сервер (VPS)            | 5 000 руб.       | Текущий       |
| PostgreSQL managed      | 3 000 руб.       | Если вырастем |
| Redis managed           | 1 500 руб.       | Текущий       |
| Домен + SSL             | 200 руб.         | Амортизация   |
| **Итого фиксированных** | **~10 000 руб.** |               |

**Break-even по фиксированным затратам:** 10 000 / 399 = **~25 платных пользователей**

**Break-even с учётом AI costs:** При марже 46% (с breakage), нужно ~10 000 / (399 \* 0.46) = **~55 платных пользователей**

### 8.5 Психология ценообразования

| Приём                       | Применение в fancai                                                               |
| --------------------------- | --------------------------------------------------------------------------------- |
| **Anchoring**               | Показывать тариф «Библиотека» (999 руб.) первым — Книгочей (499) кажется выгодным |
| **Decoy effect**            | Читатель (199) и Библиотека (999) делают Книгочей (499) очевидным выбором         |
| **Center-stage**            | Книгочей визуально в центре, выделен цветом, badge «Популярный»                   |
| **Price ending**            | 199/499/999 — классические psychological price points                             |
| **Annual discount framing** | «Экономьте 25% с годовой подпиской» (не «платите 4 488 руб. сразу»)               |
| **Loss aversion**           | «Без AI вы пропустите 80% деталей мира книги»                                     |
| **Social proof**            | «Выбор 73% наших читателей» на Книгочей                                           |
| **Free trial**              | 7 дней Читатель бесплатно → кредиты уже потрачены → lock-in                       |

```sql
CREATE TABLE credit_wallets (

CREATE TABLE credit_ledger (

    credit_type VARCHAR(15) NOT NULL,            -- 'subscription', 'purchased', 'bonus'

    description VARCHAR(255),                    -- Человекочитаемое описание
    reference_type VARCHAR(30),                  -- 'chapter_analysis', 'image_generation',
                                                 -- 'entity_synthesis', 'payment', 'referral'
    reference_id VARCHAR(128),                   -- ID связанной сущности (chapter_id, image_id, payment_id)

    -- Для кредитов с expiry
    expires_at TIMESTAMPTZ,

    -- Идемпотентность
    idempotency_key VARCHAR(128) UNIQUE,         -- Предотвращаем дублирование

    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),

    -- НИКАКИХ updated_at — леджер immutable
    -- НИКАКИХ DELETE — только INSERT
```

### 9.4 Сервис кредитов (ключевые операции)

```python
# backend/app/services/credit_service.py

class CreditService:
    """Атомарные операции с кредитами."""

    async def debit_credits(
        self,
        db: AsyncSession,
        user_id: UUID,
        amount: int,
        reference_type: str,
        reference_id: str,
        description: str,
        idempotency_key: str,
    ) -> CreditLedger:
        """
        Списание кредитов с FIFO порядком.

        Порядок: bonus (с ближайшим expires_at) → subscription → purchased

        Raises:
            InsufficientCreditsError: если баланс < amount
            DuplicateOperationError: если idempotency_key уже использован
        """
        # 1. Проверка идемпотентности
        existing = await db.execute(
            select(CreditLedger).where(
                CreditLedger.idempotency_key == idempotency_key
            )
        )
        if existing.scalar_one_or_none():
            raise DuplicateOperationError(idempotency_key)

        # 2. Блокировка кошелька (SELECT FOR UPDATE)
        wallet = await db.execute(
            select(CreditWallet)
            .where(CreditWallet.user_id == user_id)
            .with_for_update()
        )
        wallet = wallet.scalar_one()

        if wallet.balance < amount:
            raise InsufficientCreditsError(
                required=amount, available=wallet.balance
            )

        # 3. FIFO списание
        remaining = amount
        for credit_type in ['bonus', 'subscription', 'purchased']:
            type_balance = getattr(wallet, f'{credit_type}_credits')
            deducted = min(remaining, type_balance)
            setattr(wallet, f'{credit_type}_credits', type_balance - deducted)
            remaining -= deducted
            if remaining == 0:
                break

        # 4. Обновление wallet
        wallet.balance -= amount
        wallet.total_spent += amount

        # 5. Запись в леджер
        entry = CreditLedger(
            wallet_id=wallet.id,
            entry_type='debit',
            amount=-amount,
            credit_type='mixed',  # т.к. FIFO может затронуть несколько типов
            balance_after=wallet.balance,
            description=description,
            reference_type=reference_type,
            reference_id=reference_id,
            idempotency_key=idempotency_key,
        )
        db.add(entry)
        await db.flush()

        return entry

    async def grant_subscription_credits(
        self,
        db: AsyncSession,
        user_id: UUID,
        amount: int,
        rollover_max: int,
    ) -> CreditLedger:
        """Начисление ежемесячных подписочных кредитов с лимитом rollover."""
        wallet = await db.execute(
            select(CreditWallet)
            .where(CreditWallet.user_id == user_id)
            .with_for_update()
        )
        wallet = wallet.scalar_one()

        # Rollover: subscription_credits не может превышать rollover_max
        new_sub_credits = min(
            wallet.subscription_credits + amount,
            rollover_max
        )
        actual_grant = new_sub_credits - wallet.subscription_credits

        wallet.subscription_credits = new_sub_credits
        wallet.balance += actual_grant
        wallet.total_earned += actual_grant

        entry = CreditLedger(
            wallet_id=wallet.id,
            entry_type='subscription_grant',
            amount=actual_grant,
            credit_type='subscription',
            balance_after=wallet.balance,
            description=f'Ежемесячное начисление ({actual_grant} из {amount}, rollover)',
            idempotency_key=f'sub_grant:{user_id}:{date.today().isoformat()}',
        )
        db.add(entry)
        await db.flush()

        return entry

    async def refund_credits(
        self,
        db: AsyncSession,
        user_id: UUID,
        amount: int,
        reference_type: str,
        reference_id: str,
        reason: str,
    ) -> CreditLedger:
        """Возврат кредитов при ошибке AI."""
```

### 9.6 Webhook-обработка (YooKassa)

```python
# backend/app/routers/webhooks.py

@router.post("/webhooks/yookassa")
async def handle_yookassa_webhook(
    request: Request,
    db: AsyncSession = Depends(get_db),
):
    """Обработка webhook от YooKassa с идемпотентностью."""

    # 1. Верификация подписи
    body = await request.body()
    if not verify_yookassa_signature(body, request.headers):
        raise HTTPException(status_code=400, detail="Invalid signature")

    payload = await request.json()
    event_type = payload["event"]
    event_id = payload["object"]["id"]

    # 2. Идемпотентность: проверяем, обработан ли уже
    existing = await db.execute(
        select(WebhookEvent).where(
            WebhookEvent.provider == "yookassa",
            WebhookEvent.external_event_id == event_id,
        )
    )
    if existing.scalar_one_or_none():
        return {"status": "already_processed"}

    # 3. Сохраняем событие
    webhook_event = WebhookEvent(
        provider="yookassa",
        event_type=event_type,
        external_event_id=event_id,
        payload=payload,
        status="processing",
    )
    db.add(webhook_event)
    await db.flush()

    try:
        # 4. Обработка по типу
        match event_type:
            case "payment.succeeded":
                await _handle_payment_succeeded(db, payload)
            case "payment.canceled":
                await _handle_payment_canceled(db, payload)
            case "refund.succeeded":
                await _handle_refund_succeeded(db, payload)

        webhook_event.status = "processed"
        webhook_event.processed_at = func.now()
        await db.commit()

    except Exception as e:
        webhook_event.status = "failed"
        webhook_event.error_message = str(e)
        webhook_event.retry_count += 1
        await db.commit()
        raise

    return {"status": "ok"}
```

### 10.1 Итоговая рекомендация

**Модель: Freemium + Гибридная подписка с кредитами + BYOK**
