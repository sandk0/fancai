# Этап A — Direct-миграция на Gemini: дизайн (упрощённый)

**Дата:** 2026-06-15
**Статус:** дизайн утверждён (брейншторм superpowers), готов к написанию плана реализации
**Уточняет:** `docs/plans/2026-06-13-gemini-migration-plan-v3.md` (Этап A) и аудит `docs/reports/2026-06-14-gemini-migration-plan-v3-audit.md`
**Ключевая вводная:** прод fancai.ru сейчас на **~0 трафика** (ранний/тестовый этап) → себестоимость на Этапе A некритична; решения оптимизируются под **качество и чистоту кода**, а не под цену.

## Цель

Перевести оба AI-пайплайна (извлечение сущностей/описаний + генерация иллюстраций) с OpenRouter на прямой Gemini API (`google-genai==2.8.0`), **синхронно, на `gemini-3.5-flash`**, и прийти к **чистой Gemini-only кодовой базе**. Без монетизации, тарифов, batch и кредитов — всё это консолидируется в Этапе B, где у него есть реальный потребитель.

## Целевая архитектура (из плана v3, без изменений)

- **Провайдер-абстракция:** `AIProvider` Protocol + `GeminiClient` + (временно) `OpenRouterClient`, выбор через фабрику по feature-flag `AI_PROVIDER` (`gemini` | `openrouter`). Флаг обеспечивает мгновенный откат на время cutover; после стабилизации OpenRouter-ветка удаляется.
- **Удаление костыля `_inline_defs`:** Gemini Direct нативно поддерживает рекурсивный `$ref:"#"` (verified по докам Google) → Pydantic-схема передаётся в `response_schema` напрямую. Корректность парсинга проверяет eval-гейт.
- **Файлы:** создать `core/ai_provider.py`, `core/gemini_client.py`, `core/gemini_pricing.py`, `core/ai_provider_factory.py`, `services/nano_banana_generator.py`; модифицировать `config.py`, `gemini_extractor.py`, `entity_deduplication_service.py`, `entity_synthesis_service.py`, `imagen_generator.py`, `tasks/image_tasks.py`, `requirements.txt`.

## Eval-гейт (абсолютная корректность)

Гейт миграции — не «≥ 2.5 baseline», а проверка **корректности интеграции** на прогоне 3–5 реальных книг (вкл. русскую классику с транслитерацией имён):

1. **Spoiler-free = 100%** — CI-инвариант, non-negotiable (`_apply_chapter_filter` не течёт на новых структурах ответа Gemini). Блокирует cutover.
2. **Schema validity ~100%** + ноль ошибок парсинга/распаковки `usage`/ответа.
3. **Sanity извлечения** — сущности/описания реально извлекаются и выглядят разумно (ручной eyeball).
4. **Картинки генерятся** на NB2; зафиксировать наблюдаемый refusal-rate на «тёмных» сценах (вход для решения по FLUX).

Сравнение entity-count со старым пайплайном — опционально, как **bug-детектор** (резкое падение → искать баг интеграции), но **не гейт**.

## Что уезжает в Этап B (с числами-входами)

- **Batch API** (−50%, SLO 24ч/потолок 48ч) — для Free-тарифа (медленный дешёвый путь).
- **Модель по тарифу:** A/B `3.5-flash` vs `3.1-flash-lite` (−83% себестоимости извлечения) → Free=lite, Pro=3.5.
- **Image-модель/разрешение по тарифу:** NB2@1K = **$0.067/картинка** (≈1.7× от NB $0.039); NB Pro = $0.134. 10 беспл./книга: NB2 → $0.67/книга. Возможен tiering (NB для Free, NB2/NB-Pro для Pro) или выбор разрешения.
- **Free-tier лимиты Gemini** (paid-проект, per-project) — сайзинг продуктового Free.
- **242-ФЗ локализация ПДн** — P1-блокер монетизации (см. аудит): сервер в Германии + БД аккаунтов/платежей росиян; юр-проверка ДО старта B.
- **Монетизация:** тарифы Free/Pro, кредиты (`SELECT FOR UPDATE` + append-only ledger + idempotency), YooKassa (54-ФЗ: ИП/ОФД), «10 беспл./книга».
